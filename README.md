# 绘序 · DraftFlow｜工程制图智能解题网站

> **现行产品定位（2026-11-21，V11）**：网站内置各类常见工程制图题型的真实几何求解能力。用户既可直接选择题型并输入/绘制条件求解，也可通过**接入的多模态 AI**上传题图，让 AI **识图、理解题意、分析空间关系、推理解法、选择/组合几何计算工具**，在必要时提出候选构型并通过数学验证。最终输出**解题结论、逐步解法、二维工程作图，以及适用时同源的可交互三维模型和 V5 动态作图**。解题是核心，AI 是参与解题的智能分析与计算编排能力，二维/三维和动画服务于解题；不是单纯的 3D 建模网站、课程平台、固定题库或完整通用 CAD。

## 两种解题入口（并列且互不依赖）

1. **网站工具直接解题（无需 AI）**：选择题型，输入尺寸/条件、绘制原始几何或编辑模型，内置专业求解器计算并输出可检查的结果与作图过程；不能要求用户先拍照或登录 AI 才能求解。
2. **AI 识图与推理解题**：上传题图 → 多模态 AI 识别图元、题意、尺寸、投影关系、已知与待求 → 人工核对关键不确定条件 → AI 生成解题思路/候选几何约束及构造步骤 → 调用或组合网站已有解析几何、投影、CAD/约束求解器进行真实计算 → 验证空间结构、几何和线型 → 输出答案、**可复核的逐步解法、二维图、适用的三维图与唯一 V5 动态作图**。不能只识别题型然后跳转到固定工具；AI 应能辅助分析复合题和现有工具未单独覆盖的题，但未通过验证不得冒充正式解。

输入可以是经确认的结构化条件、受支持的文件或日后接入的图像识别；一般 OCR 尚不完整不应阻塞无需 AI 的题型交付。未经证实的数学、可见性或空间连接只能显示候选或未支持，不得冒充标准答案。


## AI 综合解题链与现状边界

目标完整链：**多模态识图 → 题意/已知待求解析 → AI 规划解法与提出候选约束/模型 → 调用/组合现有几何数学、投影及 CAD 工具 → 数学/工程规范验证 → 真实答案与逐步解释 → 同源二维图/适用三维图/V5**。模型不是只负责 OCR 和题型分类；也不能替代几何核的坐标、相贯、连续遮挡和实虚线证明。若条件欠定，给出多解/待补条件；暂时无可靠工具验证的题输出待确认的分析而非伪装为正式答案。

AI 接入层须支持可配置的多模态模型/服务（不硬编码供应商），经受保护的服务端凭证代理，限制图片/费用/响应尺寸并保护用户题图隐私；不可在前端、公共 Git 仓库或 Cloudflare 静态资源中暴露 API key。用户直接使用内置工具时不应依赖模型在线。

**当前已验收范围不能夸大：** 现有 recognition 目录偏向本地图元/尺寸候选、浏览器原生 OCR、人工确认；截至该计划修订，尚未验收云端多模态 AI 真正对陌生题完成“识图→推理→数学验证→二维/三维→步骤”的端到端链路。以实际代码、网络调用与独立真题验收为准。

## AI 输出自定义与解题思路（V11 新增必需能力）

**解题结果可按需生成和显示，不强迫每次都输出全部解释与图形。** 该设置属于 AI 解题与网站直接解题的共享结果展示层；用户可在解题前选择，解题后也可基于同一已验证 SolveResult 追加生成或隐藏部分内容，避免无意义地重复调用 AI/几何计算。

| 输出选项 | 默认 | 含义 |
| --- | --- | --- |
| 最终答案 | 开启 | 正式几何结果、完成图和题目结论（未验证必须醒目标记） |
| 解题思路 | 开启 | 用简洁文字解释已知/待求、核心投影/几何关系和拟采用的方法；不等于预先展示最终轮廓 |
| 详细解题步骤 | 开启 | 依据受验的 ConstructionIntent/Step，逐点逐线展示真实投影、辅助线、连接与实虚线依据 |
| 二维工程图 | 开启 | 对应题型的标准二维结果，遵守第一角法与认证线型范围 |
| 三维模型 | 空间题默认开 | 与二维共享 Geometry Scene，可旋转并双向点选；纯二维题自动标记不适用 |
| 动态作图 | 支持 V5 时默认开 | 唯一 V5 真实作图动画、暂停/回退/调速；无正式步骤时不能用预制演示冒充 |
| 结果验证说明 | 可选 | 已知条件对照、残差/分支、线型和模型完整性验证，不影响强制内部核验 |
| 文件导出 | 可选 | 对已生成且符合导出门禁的 SVG/PNG/步骤图等格式输出 |

- **讲解级别**：精简（答案/简要思路）、标准（主要作图步骤和关键依据，默认）、详细教学（关键点为何在此、辅助线如何转移、点线为何相连及虚实线理由）。即使用户关闭解题思路、详细步骤，计算内部的证据约束及安全验收仍必须执行。
- **预设模板**：仅答案、标准解题、详细教学、二维三维展示、自定义。用户可保存本机偏好并对单题覆写；模型调用应按选择的输出类型规划，避免为没勾选的三维/长篇讲解增加不必要消耗。
- **分离“解题思路”和“详细步骤”**：前者是便于学习的高层方法说明（不要求公开模型内部推理日志）；后者是从数学求解器/V5 的可复核作图动作生成的步骤。图文与每个对象/步骤 ID 对齐，不是先编答案再配文字。
- **结果复用与状态**：同一 problem revision / branch / SolveResult 按需切换已计算的结果视图；选项变化通常只重新生成展示/解释，不修改几何证据。用户修改题图/条件时必须使旧结果、3D 与 V5 同步失效。无相应可信计算/可视化证据时标记“不支持/未验证”，而非让 AI 编造。
- **多端体验**：设置采用少量开关和预设，移动端默认折叠高级设置；图纸区优先显示结果，思路与步骤可展开。直接工具求解也能选择答案/步骤/图纸，AI 独有的自然语言讲解按服务可用性启用。
- **验证**：分别测试只要答案、关闭解题思路但保留详细步骤、仅二维、空间题二维三维同步、纯二维题请求三维的拒绝/禁用、讲解级别切换、失败/未认证题关闭验证说明时仍不输出伪标准答案、恢复偏好和旧版本失效。不能将文档配置视为设置 UI 已开发。

## 常见题型一级模块（按解题目标分类）

| 一级模块 | 子能力/典型问题 | 2D / 3D |
| --- | --- | --- |
| **平面图形作图** | 正多边形、圆/线段等分、相切与圆弧过渡、斜度与锥度、长圆/对称轮廓、按尺寸完成复合平面图形 | 原则上纯二维 |
| **点线面投影** | 三面投影、投影关系、点线面的位置与求作 | 需要空间理解时联动 |
| **三视图与补图** | 补第三视图、补缺线、判断对应点线 | 同源二维三维 |
| **组合体读图与作图** | 叠加、切割、组合体三视图及线型判断 | 同源二维三维 |
| **截交线** | 基本立体与截平面、截线求作 | 同源二维三维 |
| **相贯线** | 立体相交、特殊点与相贯线投影 | 同源二维三维 |
| **轴测图** | 正等测、斜二测及已知视图的轴测构造 | 按题意使用三维 |
| **综合工程图题** | 剖视/断面、尺寸标注、混合几何约束等，按可验收范围逐步拓展 | 按题型 |

**圆弧连接不是一级模块**，而是“平面图形作图 → 相切与过渡圆弧”的子功能；保留已存在的求解器、测试及老链接，通过适配接入新分类，不因重新分类删除有效代码。一级题型不是当前全部已实现的宣称，具体以验收清单标注“正式支持／实验预览／未支持”。

## 当前唯一开发计划（V11｜2026-11-21）

**以解题能力为中心、常见题型并行交付**，执行细则见 [V11 正式计划（保留旧文档路径作为唯一执行入口）](docs/architecture/DA-OPEN-SOURCE-ACCELERATION-REUSE-20261025.md)，交付总单见 [Issue #377](https://github.com/07xh/engineering-drawing-study/issues/377)。

- **P0：先把已有可验收求解器接成网站可用功能**，建立统一题型入口及已实现/预览/未支持的能力矩阵；“平面图形作图”优先整合现有圆弧/相切工具，同时覆盖常见平面作图任务，不能只把圆弧连接改名即算完成。
- **P1：并行扩展常见空间题**：点线面、三视图、组合体、截交、相贯、轴测图各自依据现有代码、求解缺口和可交付闭环推进；C1 仍是重点数学攻关，但不再是所有题型交付的全局阻断。
- **P2：接入多模态 AI 参与综合解题**：不仅识图和路由，还要理解题意、推导候选解法、组装几何约束、选择/组合内置数学/CAD 工具、检查不确定和多解，并将验证后的几何与解释绑定至二维、三维和 V5。优先复用同一套求解器，但不把 AI 限死为固定题型分类器；图像理解、推理编排与数学、工作台并行研发。不得将 AI 的文字/示意图当作有证工程图。
- **P3：完善二维/三维同源联动、V5 步骤与交互**：共用唯一 SolveResult、Geometry Scene、ConstructionIntent/Step DAG 和 V5，纯二维题不制造虚假三维。

原 V9/V10 中“C1 必须先独占全部研发资源”“以单条数学反例代替多题型网站交付”“圆弧连接作为一级题型”的任务排序不再生效；原有已验证算法、反例、核心证据与 [#372](https://github.com/07xh/engineering-drawing-study/issues/372) 数学门禁、[#152](https://github.com/07xh/engineering-drawing-study/issues/152) 合并/发布边界、[#497](https://github.com/07xh/engineering-drawing-study/issues/497) 唯一 Scene/V5 继续有效。原 2026-11-20 首版目标已过期，不得当作已上线凭证。

## 现行架构及代码门禁（以 #372、#152、#497 为准）

- **唯一计算主线**：人工确认的 ProblemDraft → M0 数值与单位 → M1 几何拓扑/约束结构 → M2 通用残差、分支、局部自由度与证据 → M3 专业解析/构造求解 → 版本化 SolveResult/Geometry Scene → 第一角法 V/H/W 及三维共享呈现 → ConstructionIntent → ConstructionStep DAG → **唯一 V5 时间轴** → M5 独立题图/数学/动画/线上验收。
- **不可一题一开发**：禁止按某道教材题写特判、预制答案、单独求解引擎或动画播放器。点线面、网格、投影、可见性、对象 ID 和修订失效应抽成可复用数学及表示能力；专业算法只提供可核验的几何证据。
- **强制分层边界**：M2 不得反向依赖 M3；可信求解与显示/相机变换隔离；2D/3D 属于一个数学场景的多视图，未证明的遮挡、分支和唯一性必须 fail closed。纯二维题不能凭空制造三维结果。
- **现行提交机制**：以 `main` 为基线，独立分支与 PR、检查 diff、适用数学反例/安全/回归测试、当前 HEAD 五类 CI 全绿且可合并即 squash-merge；不等待 00/09 外部人工批准。当前 main push 的 GitHub Actions + Wrangler 条件发布链、历史 Cloudflare Builds 停用状态、Production Active SHA、真实浏览器与 Android 验收分别核实；未知触发生产时停止合并，不因文档改动跳过发布授权，不把 PR 或 CI 视为上线。
- **规则权威**：[数学及证据 #372](https://github.com/07xh/engineering-drawing-study/issues/372) · [开发/合并/发布 #152](https://github.com/07xh/engineering-drawing-study/issues/152) · [共享 Geometry 与项目工作台 #497](https://github.com/07xh/engineering-drawing-study/issues/497) · [圆锥真实缺口 #504](https://github.com/07xh/engineering-drawing-study/issues/504)。旧版本号、早期 R0–R3 阶段表和历史 Issues 只作历史，不得替代现行规则。

## 当前可用与尚未完成

- **已合并代码（不是完整验收）**：#394–#396 的二维正式意图/V5 主链；#495、#499、#502 的本机协调/存储/确认 API；#503 的受限圆锥截线分类和无交线展示；#505 的共享 Geometry Scene；#506 的极大坐标方向及 mm 单位校验。以上均不是任意工程制图题自动完整解答。
- **目前明确未完成**：真实公共图像审核与本地项目 UI、完整文件导入导出、一个会话下的二维/三维选择及 V5 同步、非椭圆有限圆锥截线、全部虚实线证明、未带答案原题整题盲测、Cloudflare Production Active 与 Android 实机验收。按 #497/#504 修复，不以新框架或演示页面替代。

- **已存在的基础工具**：部分点的三面投影、平面图形作图所需的圆弧/相切等子求解器、几何约束与自由度分析、辅助作图和其他专项实验页面；实际支持的条件应以各工具说明和通过的测试为准。
- **尚不能宣称已完成**：对任意新图片的端到端 AI 自动识别、通用求解、自动作图及完整私人题图上传服务。研发任务或绿色 CI 不等于这些能力已交付。
- **辅助功能**：原有教材与教学研究代码可以作为数学样本或参考，但不构成产品首页、主要使用流程和新增开发的优先级。

## 使用环境与安全边界

优先兼容 Android 平板、手机及桌面浏览器，重视手指/手写笔操作和图纸可读性。

公共站点只发布经过白名单构建的基础工具；未建立完整身份认证、私密对象存储和上传限制之前，不开放私人题图上传，也不在公开 GitHub 仓库或 `dist/` 存放原始教材、个人习题照片或模型密钥。README 的功能目标与目前已部署能力必须明确区分。
