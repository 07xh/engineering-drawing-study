# M0 continuous clearance: false-zero observer slope cannot prove support-plane clearance

An existing generic continuous segment→convex-solid ray clearance kernel allowed a rounded zero `dot(normal, observer)` to pass the sufficient 'nonnegative common exterior support' test. For real binary64 direction with **exact negative** dot this is unsound: a ray can travel toward the support plane at large positive depth, so caller must not deduce a globally clear ray from approximate parallelism. The same false-zero coefficient could be eliminated as a depth-independent constraint in Fourier–Motzkin geometry.

This small patch consumes the single opt-in exact dot-sign evidence from merged #629. Outward-support `slope>tolerance` now also requires genuinely positive represented-binary64 sign; exterior-support `slope>=0` requires nonnegative exact sign, and the depth coefficient branch treats `beta===0` as parallel only when its exact sign equals zero. Otherwise it returns existing fail-closed `undetermined`, without inferring the farther halfspace depth bound. No new tolerances, source representation, V5 engine, full-scene certificate or solver. All old numerical dot, parameter, residual and Fourier–Motzkin path outputs otherwise remain.

Independent tests prove an adversarial normal/observer pair whose rounded dot is 0 but exact sign is -1, reject false segment clearance, preserve true parallel positive clearance, standard finite box source clear ray and strict degenerate inputs. Existing M0/M3/M4/M5 and exact HEAD five CI required before squash. Rollback via isolated revert.
