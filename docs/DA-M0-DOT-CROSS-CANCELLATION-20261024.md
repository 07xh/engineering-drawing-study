# M0 checked dot / cross: stop false-zero cancellation without a second kernel

The original shared Euclidean Float64 kernel already refuses direct nonzero multiply underflow but could falsely produce ZERO when several distinct large product terms cancel through IEEE rounding. Example `dot([1,1,1],[1,2^-53,-1])` returned zero even though exact represented-binary64 dot is positive `2^-53`. The 3D cross component `(2^52)(2^52-2)-(2^52-1)^2` returned zero despite exact signed value -1. False zero can be mistaken for a perpendicular/collinear geometric condition.

This patch stays inside `core/numeric/euclidean-kernel.cjs`, used by `object-vector3.cjs` and real 04/M3 and M0/M5 consumers. The existing `dot` and `cross3` Float64 number APIs remain exactly as before because actual 04/M3 solver consumers already use local tolerances and cannot switch to exceptions in numerical near-tangencies. Instead NEW opt-in `certifyDotSign` and `certifyCross3Signs` expose the mathematically exact sign of the represented binary64 coordinates alongside their old rounded value. For cancellation-risk cases only, they reuse the **single existing** `binary64-dyadic.cjs` engine. A rounded 0 with exact nonzero sign is reported openly (`signMatchesRounded:false`), not turned into a fake geometric zero. This makes the evidence usable only by callers that explicitly request a sign proof and protects existing M3 compatibility. Neither signs nor approximate magnitudes imply full visible/hidden line proof.

Also close a validation/consumption time-of-check/time-of-use bug: `vector()` snapshots getter-backed finite coordinates once, including sparse index checks, instead of validating first and then re-reading spread values that may have mutated.

Tests independently derive the 2^52 cross determinant via BigInt, 2^-53 positive/negative false-zero dot signs (while rounded results stay backward-compatible), exact cancellation and standard perpendicular normals, getter single-read, 99 geometric scalings, nonfinite, sparse, dimension and underflow negatives.
