# M0 projected finite edge depth: robust proof before collinear-overlap (2026-10-24)

The shared `projected-edge-depth-events.cjs` previously used a raw Float64 cross-product `r.u*s.v-r.v*s.u` with an absolute tolerance to classify two projected finite segments as parallel, followed by another rounded cross check to consider them collinear. **Counterexample with legal source coordinates <= 1e8 model mm:** `r=(1e8,1e8-1)`, `s=(1e8-1,1e8-2)`. The rounded cross is 0 but the exact represented-binary64 cross is -1 (independently checked with BigInt). A pair of such noncollinear projected lines could be declared a `collinear-overlap` continuous range, which is mathematically false.

Minimal fix: only when entering the nearparallel Float64 path (not standard crossings), consult the SINGLE existing `orientation2d-adaptive.cjs` predicate for the direction signs and projected SOURCE a/b/c/d incidence. If their exact represented-coordinate directions differ, return `undetermined-near-parallel-projection`. If direction values seem parallel but either projected foreign endpoint is not exactly on the first line, return `undetermined-near-collinear-projection` unless a separated, same-sided far-parallel test already independently proves disjoint. ONLY precisely collinear represented endpoints continue to the original overlap-parameter and depth-swap logic.

No new coordinates, tolerance, line style, source depth system, point projections, parallel engine, ConstructionIntent or V5. Proof is limited to two supplied projected source edges and the represented binary64 input values, not an original image/camera or entire scene.
