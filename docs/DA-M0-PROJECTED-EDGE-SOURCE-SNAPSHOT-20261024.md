# M0 projected edge depth source single-snapshot integrity (2026-10-24)

After the shared exact represented-binary64 collinearity guard merged in #638, source correctness still depended on input reads: `inspectProjectedEdgeDepth` previously checked `point(p)` by reading x/y/z (even twice per coordinate in `finite(p[k]) && abs(p[k])`), then independently accessed `edge.from`/to/id and projected those mutable caller objects again. Getter-backed or changing source coordinates could therefore pass finite/identity validation but alter the mathematical ray, depth or projected endpoint when consumed.

This small change preserves existing 3D edge contract (`{id,from,to}`), finite model-3d unit bounds, tolerance, first-angle V/H/W, depth order/overlap structure, and all negative proof flags. It creates one detached finite x/y/z snapshot of each input edge and stable ID **before any projection or mathematical proof**. Each input coefficient and row/edge identity is read exactly once, no re-import/reimplementation of geometry math. The original first-angle shared projector and exact orientation guard still own the calculations.

Independent tests reproduce dynamic getter second-read Infinity, shifted 3D endpoint z causing reversed depth order if reread, changed identity, top-level from object mutation; reject bad first reads, sparse coordinates, duplicate stable IDs, and preserve exact near-parallel, ordinary H crossing and no scene/line-style/V5 promotion. All five exact PR HEAD CI must succeed before merge, isolated revert for rollback. This is source shape integrity only, not authentication of a scanned image, revision or entire CAD scene.
