# DraftAI 08 V3.3｜图元候选 → 原图字段来源关联（非 OCR）

依赖已合并的 #254 原图字段逐项确认、#256 线段候选、#257 圆和圆弧候选、#245/#246/#248 数学解算与 V5 会话。总控 #240，08 #234，09 #243。

## 新工作流程
1. 用户仅在浏览器本地打开原题图，点击直线或圆/弧候选检测；每个候选有图像像素 `bbox`、候选 ID 和类型。
2. `recognition/source-candidate-link.cjs` 将下采样分析帧 bbox 映射回**原图像素尺寸**，验证数据有界，**不做像素→工程毫米换算**。
3. 在严格核对模式选中“线段一 X”“圆一半径”等待关联字段，从候选下拉框明确挑选一个线/圆/弧，点击“关联到当前条件”。系统只将检测候选区域作为该字段的**原图证据框**，尚未确认工程数值；不会覆盖输入框。
4. 继续使用已有“确认当前数值与框选区域相符”逐项核对、再点击“确认全部条件并解题”。只有这一独立用户接受流程通过才会获得受控 `ProblemDraft`，由 01/02 数学解算器和 V5 运行。
5. 修改数值、选择别的候选框、替换照片会使旧确认及数学动画失效；记录用于追溯的 `detectorCandidateId`，它既不保证识别正确，也不是唯一答案的证据。

## 数据和安全边界
- 候选线段/圆/弧只是 **untrusted image-px proposals**，原图来源 bbox 以明确的原始图片宽高为准。
- 严格拒绝 NaN、空/越界候选框、非图元类型、非法 ID 和超出受支持大小的输入。
- `image-field-review` 只传已逐项核对的有限毫米值给数学引擎；保持用户选分支与两侧 G1 验证。
- 不增加网络请求、存储、服务器上传、OCR、密钥或任何私有图片资产。

## 验收
`node --test tests/workbench/v33-candidate-source-review.test.cjs` 检查原像素 bbox 转换、异常/伪造候选、只关联不确认时阻止数学求解、最后用户确认后真实 math/G1/V5 的状态，以及修改半径后的确认失效。需要最新 HEAD 的全套 GitHub CI 和后续浏览器真机操作。此工作仍不等于“任意二维图全自动识别及求解”。

下一步应是模型侧的尺寸文字 R/Φ 检测与文本-图元关联、相机透视校正和难例集回归；其输出也必须通过本人工/数学验证边界。
