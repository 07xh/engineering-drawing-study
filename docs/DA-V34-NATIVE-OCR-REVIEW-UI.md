# DraftAI V3.4｜本地 OCR 尺寸候选接入原图核对

依赖 #265 的浏览器原生 TextDetector OCR 执行器、#261 的 R/Φ 严格尺寸解析与 #259 的图元来源核对。总控 #240，08 #234。

## 新增体验
1. 在 `/labs/auto-fillet-live.html` 本地加载 JPG/PNG/WebP 原题后，选择“识别 R/Φ 文字（实验）”。
2. 支持 TextDetector 的浏览器会在本地缩放 Canvas 上识别文字，过滤出语法明确的 `R12`、`Φ20` 等，映射回原图尺寸框，以橙色虚线标记。
3. 从下拉列表选择候选，会显示它的**待复核半径建议**和基于图像框距离排序的可能圆/圆弧来源。未写明 mm 时显示“图纸单位尚未核实”。
4. 仅在**严格人工核对模式**下，选择 `filletRadius` 或 `r1`/`r2`，点击“将所选 OCR 位置关联到半径条件”。这个操作只保存来源 bbox，不修改原有数字输入框、不确认半径、不选择数学解分支。
5. 用户仍须填写正确的毫米数值、点击“确认当前数值”，并对全部必需条件执行最终确认。只有满足既有 01/02 G1 求解器的输入与证据门槛，才能生成 V5 动画。

## 安全和兼容
- OCR 仅在点击后执行。无 TextDetector 时显示明确“不支持”，没有远程服务或捏造检测结果。
- 换图片、清图、图片加载失败会撤销 OCR 候选；**异步 OCR 检测完成时也必须检查源图 epoch**，不能把旧照片识别结果展示在新照片上。
- 文字建议不会自动改工程单位、复制为数学真值或让 `session.replace` 绕过现有严格模式。
- 这是**可选的有限浏览器原生 OCR 体验**，无法保证 Android 浏览器的 TextDetector 可用，不等价于自带高准确率 OCR 模型。未做真实 Android UI 操作和 Cloudflare Active SHA 验证。

## 回归测试
