# DraftAI V3.5 · 08-C6: local raster geometric source review

**Goal:** use actual line/circle candidates from a PNG/JPEG/WebP photo as editable pixel geometry in the existing **personal engineering-drawing solver**, not another illustration or course.

## Implementation

1. Existing `labs/local-line-candidates-ui.cjs` and `labs/local-curve-candidates-ui.cjs` preserve their existing display candidate callback and add an **optional second metadata argument**, retaining bounded original analysis detector pixel coordinates, analysis image size and original image size. Current overlays/OCR leader ranking are unchanged.
2. The new `labs/local-raster-geometry-review-ui.cjs` uses `candidateDraftFromRaster` (#272) to show **safe reconstructed segments and whole circles**, with pickers matching the selected fillet type, editable original-photo pixel endpoints/centers/radii, a separately user-entered mm-per-pixel scale, origin coordinates, Y direction and positive fillet R. Partial arcs may appear in the unconfirmed draft, but cannot be selected as a whole circle. No raw image becomes HTML or is stored.
3. `labs/local-raster-fillet-import.cjs` takes only two explicitly chosen finite lines/complete circles and **fully enumerated corrected pixel geometry**, enforces current draft revision, source kind, bounded coordinates, positive metric scale and explicit review checkbox. All other candidates are rejected. It calls the existing #250 `prepareConfirmedFillet` exact-version model-mm adapter and #255 `formFields`; no math or V5 code is duplicated.
4. New panel on existing `labs/auto-fillet-live.html` is wired in `labs/auto-fillet-live-entry.cjs`. On a valid import it copies reviewed numbers to existing form fields, **enables strict original-image source-field review**, clears previous field approvals, clears branch/direction/travel choices and invalidates old V5 session. The user must still confirm each field plus final acceptance before true 02/G1 math may run. The attached photo stays local.
5. Original image pixel geometry is only an *estimated* source hypothesis. User-confirmed mm-per-pixel is **not independently proven**. The derived mathematical answer is only as reliable as the manually verified geometry and scale. Neither OCR candidate proximity nor pixel confidence chooses a branch or establishes global uniqueness.

**Boundary conditions:** no inferred mm scale, no automatic select, no hidden calibration, no partial arc promoted to whole circle, no on-device remote OCR, new backend upload, persistence, auth, CI workflow or build target. The new test `tests/workbench/v35-raster-geometry-metric-review.test.cjs` runs three real existing finite-fillet G1/V5 cases plus invalid ID, stale revision, missing consent/scale, nonfinite/oversized corrections, unsupported partial arc, strict UI wiring and original-image source resets. Revert one squash PR for rollback.

**Still open:** freeform engineering drawing contours, perspective-corrected photo geometry, real-world mobile ergonomics and OCR coverage, three genuinely unfamiliar photographed engineering-drawing problems from image pixels to independent math-verified animated solution, production Active SHA. The current public workbench remains a constrained three-kind finite segment/full-circle fillet tool.
