# DraftAI V3.5 08｜分裂 OCR 文字的保守 R/Φ 尺寸重构

## 解决的问题
一些浏览器原生 TextDetector 会把工程图 `R8`、`Φ20` 分裂为 `R`+`8`、`Φ`+`20` 两个独立原图文字框。此前严格解析器只支持一个完整文字框，因此出现漏检。

## 改动
1. `joinSplitDimensionTokens()` 只尝试相邻、同一基线、相近高度的 **R/r/Φ/φ/Ø/ø/⌀/∅ 标记**和**有限正数**。水平距离、重叠程度和文字框尺寸必须满足严格上限；M20、O20、公差、远离文字、不同文本行不会被拼合。
2. `normalizeNativeDetections()` 先保留原生整体文字识别结果，再把每个合法分裂组合当成**额外待确认候选**，记录两个 OCR 来源 ID、原始像素框和 `syntheticJoin:true`。同位置、同类型与数值的整体识别优先，不重复展示。
3. 若一个前缀与多个数值相邻，**保留多个选项，不强行判定唯一**。仍仅在支持 TextDetector 的本地浏览器可用，不联网。
4. 所有组合结果继续 `confirmed:false`、`requiresHumanReview:true`，不能直接写入毫米条件，更不能越过 02 数学和 V5 的验证。

## 验收
新 `tests/workbench/v35-split-dimension-ocr.test.cjs` 覆盖 R/Φ 合并、像素回映射、伪标签/斜行/远距离不合并、多个候选、不重复展示、资源限制和 OCR/数学隔离。执行完整主仓库 CI，避免修改任何 Cloudflare 生产环境。

局限：本 PR 不是 OCR 引擎本身，也不解决引出线角度、箭头识别、三维空间约束或 100% 的字符检测准确率。Android 浏览器支持与正式域名需另行实机验收。
