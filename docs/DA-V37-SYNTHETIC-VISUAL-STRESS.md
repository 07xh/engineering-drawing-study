# DraftAI V3.7 · 可重现扰动下的识图回归诊断

接续已合并 #286/#287 的图元质量量化评测，增加对实际检测器在**扫描图风格扰动**下的召回变化和误检数量统计。

## 本次覆盖

在已有自制有限直线、圆、圆弧及空白页合成图上，不改变真值图元几何坐标，运行四种确定性像素扰动：

1. **低对比度**：降低笔画与纸张亮度差。
2. **纸面背景渐变**：模拟照明不均匀。
3. **零星杂点**：使用位置决定的伪噪点，无随机状态，保证不同 CI 可复现。
4. **断墨点**：将部分深色笔画像素恢复为白色，检验对缺损笔画的耐受性。

对每个原样本及每种扰动，真实运行 `detectLineCandidates` 或 `detectCurveCandidates`，再用 #286 的一对一指标引擎计算 TP/FP/FN、召回率、误检 ID 和漏检 ID。报告 `deltaRecall` 与新增误检数，单独列出所有退化案例。**不会删除、篡改原像素或用一个候选匹配多个真值**。

## 如何复现

```sh
node scripts/report-recognition-stress.cjs
node --test tests/workbench/v37-synthetic-visual-stress.test.cjs
```

工作台 CI 将执行该测试，确保基准图样上的已知正例仍能被检测、扰动报告结构正确、空白页及未定义召回率保持诚实、来源文件不读取用户原图。

## 重要边界

该数据仍是**自制合成 RGBA 及确定性像素变化**，不是现实手机拍照工程图的分布，更不是实机 OCR 质量。报告显式 `realPhotoCount:0`、`browserOcrRuns:0`，退化统计不应作为市场宣传的识别准确率。

扰动中召回率下降是应当被发现的诊断信号，而不是隐藏数据或通过降低测试标准来消除。正式引入算法优化前，应优先修复可复现的误报/漏报并增加授权的未见真实工程图样本、图元与标注双人复核，最后在 Android 浏览器上真实验收。

本 PR 仅更新 tests/scripts/docs，不覆盖并行 #279 像素→V5 集成，也不修改数学求解器、CI 共享工作流或 Cloudflare 生产设置。关联 #234/#240/#243。
