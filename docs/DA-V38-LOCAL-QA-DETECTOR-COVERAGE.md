# DraftAI V3.8｜本地识图质量验收的检测范围与缺失机制

本增量修复 #294 本地真实图片验收实验室存在的一个**统计意义上的错误**：用户虽可标注 R/Φ 尺寸文字，但页面此前没有真正运行 TextDetector OCR。未调用模型，不能算成“模型发生一次文字漏检”。

## 新约定
- 识图实验室对直线、闭合圆、圆弧继续运行 08 既有实际像素识别器。
- 现在对同一个本地 RGBA 分析帧与线段候选，还会真正执行 `detectArrowWingCandidates`；在原图像素坐标标出候选箭头尖端并纳入箭头 TP/FP/FN。**这仍仅为局部 V 形笔画，不代表已验证工程箭头。**
- `dimension` OCR 文字类别标为 `notRunKinds:['dimension']`；单独或混合标注的文字框不会进入 OCR 召回率分母。
- 如果用户只标注文字，报告返回 `needs-evaluable-annotations`（“OCR 未运行，无法计算准确率”），而不是假造全零召回的报告。和圆/线混合标注时仅对真正执行的识别器计算指标，记录 `unevaluatedAnnotations`，保留原始真值。
- 清空、换图、手工回退都沿用 #292 的会话修订号与 #294 的页面生命周期，不保留图片像素。
- 不更改 01/02 几何求解器，也不把“疑似箭头”当作证明、有向 G1 或工程毫米条件。

## 验收
`node --test tests/workbench/v38-qa-detector-coverage.test.cjs`

新增负例证明只有文字标注时不会虚构 OCR FN；混合标注时文字被明确排除；程序生成的真实 RGBA 短翼线段会实际经过**当前 Hough 检测器 → 当前箭头检测器 → 一对一评测**。再次要求全部 GitHub Actions 成功才能合并。

**未来可选 OCR 的下一步**：仅在用户明确启动、浏览器支持原生 TextDetector 时允许真正 OCR 检测，并显示它的执行状态。不应在不支持时自动上传照片或调用未经审查的外部服务。
