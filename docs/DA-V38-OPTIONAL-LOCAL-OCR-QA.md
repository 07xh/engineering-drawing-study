# DraftAI V3.8｜可选原生 OCR 与真实本地图片质量评测

## 新增行为

用户在 `/labs/recognition-qa.html` 本地加载自己制作或拥有使用权限的工程题图，先运行有限直线、圆/弧和疑似箭头检测；现在可以**另外主动**点击「本地 OCR 检测 R/Φ（可选）」。

仅当前浏览器提供原生 `TextDetector` 时，该按钮在设备端 Canvas 上执行真实 `detect()`，将 R/Φ、Φ/Ø/⌀ 尺寸标记等由严格解析器识别的候选，以原图像素框与手工真值文字做一对一匹配。**没有 TextDetector 就明确显示 OCR 未评测**；绝不伪造 OCR 答案，也不自动上传至任意云端 API。

## 两项防误导统计
- **未运行 OCR ≠ 漏检。** 文字标注不参与召回率分母，除非 TextDetector API 确实成功返回候选数组（包括空结果）。运行成功但没有识别出已人工标注的 R/Φ 时，才是合法 FN。
- **没有手工标注的类别 ≠ 自动全部误检。** 例如只标注一处 R12 时，其他检测到的圆和直线不应被错误纳入文字精确率的 FP。现在在 `scoredKinds` 列出实际评分的类别，`unscoredKinds` 列出仍未评测的类别。**即使已经选中某一类，用户也应标齐该类在图片内的全部真实对象，才可解释该类 FP 统计。**

## 异步/隐私安全
- 每次更换照片、重新运行基础检测或关闭页面，都会使旧图的 OCR 结果无效；同时为每次 OCR 操作维护单独的请求代号，以免过时识别结果重新启用/覆盖当前页面。
- 文字候选严格验证 ID、来源坐标 `original-image-px`、原文有限长度、候选数量与边界；只在当前 `imageVersion` 一致时以原子方式进入会话。异常数据不得污染已存在报告。
- 图片 RGBA、原照片文件名、浏览器会话令牌没有保存到导出 JSON。仍由用户主动点击导出报告，不使用 fetch、XHR、localStorage 或第三方 JS CDN。
- 精确率/召回率只表示本张图与人手标注之间的候选吻合度，**不是独立审核的真实工程照片大规模性能统计、更不是由几何内核认证的毫米/G1/V5 答案**。
