# DraftAI 09 V3.9｜识图人工真值标注的可重复导入契约

## 为什么要做

此前 `/labs/recognition-qa.html` 可以检测图片、人工标注、导出本次误差报告，但刷新或重新检测后需重新标注同一张图片，无法可靠复测算法版本的改进。本模块为**用户明确选择的图片**建立严格本地标注基准格式。

## 数据契约

`createAnnotationPack(snapshot,sha256)` 创建 `draftai-photo-annotations/1` 标注包，仅包含：
- 原始图片固有像素宽、高；
- 由浏览器对原始图片字节计算的 SHA-256 摘要（64 位十六进制）；
- 人工确认的有限直线、圆、弧、文字框、箭头尖端几何数据，均为 `original-image-px`；
- **明确提示**：手工转写的文字和图片哈希可能带有识别性，不等于匿名、不等于数学证明。

无图片字节、原文件名、照片 EXIF 或用户认证信息。

`validateAnnotationPack(pack,{image,sha256})` 必须同时验证：schema、图片宽高、SHA-256、严格原图像素坐标、最多 100 条真值、唯一安全的 `truth_N` 标注 ID、全部被识别的字段，拒绝额外字段和异常几何。哈希不匹配时即使宽高一样也**不得复用旧标注**。

`createPhotoQualitySession().restoreAnnotations(expectedImageVersion,pack,sha256)` 在数据全部验证后一次性替换人手标注。源图 revision 不同则直接返回 false；非法/伪造内容必须保持旧标注及当前检测候选完全不变。导入只改变真值，不绕过 TextDetector 是否真实运行、人工完整性或 01/02 数学解答验证。

## 威胁模型与限制

SHA-256 只是“是否是同一个图片文件”的本地复测线索，不是内容许可证明、人工真值签名或用户身份验证。哈希可用于识别两份是否来自相同图片，**不应把标注包称为匿名数据或无条件公开**。不使用远程服务、私有密钥、localStorage、数据库或图片持久化。

这份 PR 交付校验底层；下一 PR 将新增用户明确点击的导出/导入按钮，在浏览器本地通过 Web Crypto 对所选图片文件计算 SHA-256，并核对后调用上述会话方法。不会在页面加载或文件选择时自动上传图片。

## 测试
`node --test tests/workbench/v39-photo-annotation-replay.test.cjs`：正常生成与重载、原图更换、相同尺寸不同文件、SHA 错误、文本过长、越界坐标、重复标注、夹带私有图片字段、过多标注、零副作用拒绝和 ID 保持。另须通过仓库全部 GitHub CI。

工作流仍是“本地题图→识图候选→人工真值→像素误差”，不宣称任意工程图自动解答或真实安卓 OCR 准确率。
