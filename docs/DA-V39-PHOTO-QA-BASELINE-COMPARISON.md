# DraftAI V3.9｜单张工程题图识图质量基线比较

继 #301（严格图片指纹绑定人工标注）和 #303（浏览器中明确导入/导出同一题图标注）后，本轮补齐“**同一批人工真值，用新版识图算法复测后，究竟改善还是退化？**”的问题。

## 用户流程

1. 本地选择自有/获许可题图，运行线段、圆/弧、疑似箭头及可选原生 OCR。
2. 在图上标齐要评测的类别的全部真实对象；可以先通过 #303 导入此前同一张图片的标注。
3. 点击「**保存本次质量基线**」：浏览器仅在主动操作时计算原始图片字节 SHA-256 和手工真值 JSON 的 SHA-256，并导出 `draftai-photo-qa-baseline.json`。
4. 下一次代码更新后，重新在浏览器中选择**字节完全相同的图片**，运行新的检测，再导入相同的人工真值。
5. 在「选择以前保存的质量基线 JSON」中选择基线，点击「**核验条件并对比结果**」。若照片指纹、标注指纹、图像尺寸、参与评分的类型、未运行的检测器、算法指标契约版本都相同，显示各类型 TP、FP、FN、精确率、召回率和 F1 的变化。否则直接拒绝，并报告不可比的原因。
6. 对比结果只是页面上的**单张图诊断**，不会上传图片或静默替换用户的基准；手工标注不完整或存在错误时，分数同样会误导。

## 比较的安全性和诚实边界

- 比较不依赖同名文件，也不依赖相同宽高。SHA-256 不可当作匿名化或真实照片许可证明。
- `manualTruthSha256` 对**完整原图像素标注与人工转写文字**生成摘要，标注更改 1 个像素或 1 个字都应拒绝直接比较，避免低质量标注导致假进步。
- 只比较实际参与评分的图元类别（`scoredKinds`）且未运行检测器列表必须相同；不能把 TextDetector 不支持的结果与它已运行的结果直接评价为整体算法提升。
- 任何类别的标注数 `TP + FN` 必须前后相同，且 TP、FP、FN 都必须是有限非负整数。拒绝未知文件字段和不兼容的评测规范。
- 不在报告中存储照片 RGBA、Blob、原文件名或人工文字全文；摘要是**可识别性较强的指纹**，仍不应无条件公开。
- 页面每次图片更换、人工标注编辑和重新识别都会废弃旧比较显示；在文件读取和摘要计算期间也检查照片与会话版本，拒绝过期结果。
- 这只能用于“同一张图片、同一真值”的回归诊断，不代表跨图片/跨设备总体准确率，也不能认证工程毫米制图、自由度、G1 或 V5 的数学证明。

## 验收

回归包括：相同基线零差异、故意改变误检/漏检的结果、不同图片/标注或检测范围拒绝、真值分母变化拒绝、恶意附加字段、原生 SHA-256 计算及页面静态接线。并执行五组 GitHub CI；最终 Cloudflare Active SHA 和 Android 触控/OCR 真机仍需独立验收。
