# DraftAI 09｜V4.0 安卓触控识图人工标注坐标与取消规则

## 为什么修改

原来的 `/labs/recognition-qa.html` 只在原始适屏图纸上提供固定的鼠标/手指拖动画图。对手机拍摄的高像素工程图，按适屏宽度很难定位小箭头/细线；双指触碰、指尖离开绘图区、浏览器取消捕获等事件，可能把一段尚未完成的动作错误保存为人工真值，污染后续 TP/FP/FN 质量评测。

## 本轮实现

- 在原网页新增 **放大 + / 缩小 − / 原始适屏** 三个可操作按钮（100% 到 300%，每次 25%）。图片和 SVG 标注层处于**同一个相对定位的可滚动放大容器**，不会出现“图放大了、绿色标注层却没有缩放”的失配。缩放不重跑识别器、也不修改用户原图坐标或现有标注。
- `imagePointFromClient` 必须使用 `overlay.getBoundingClientRect()` 在**当前浏览器实际布局下**映射 clientX/clientY → 图片固有像素尺寸；不复用上一次的元素宽度，也不推测浏览器缩放、滚动或设备 DPR。即使缩放、纵向图纸、容器移动，仍得到同一张原图上的同一像素坐标。
- `createPhotoQaGesture` 只接受单个有效指针 ID 完成标注。双指接触会取消这一笔，直至双指都释放后才能新建；`pointercancel`、`lostpointercapture`、更换/清空照片、重新运行检测和缩放中断均作废当前手势。
- 如果在图外抬起指针，拒绝把“最后一个有效的移动点”当作用户确认的最终端点，避免无意生成伪标注。
- 事件仅更新**人工真值**的图层，无法自动绕开单次浏览器 native OCR 或 01/02 数学 G1 求解。画像、坐标、真值仍完全保存在本地内存和用户主动下载的 JSON 中。

## 有界验收

新增 `tests/workbench/v40-photo-qa-pointer-geometry.test.cjs`：常规原图像素/横纵坐标、2.5 倍放大与滚动后的坐标等价、手机竖版图纸、指针越界、非法 DOM 矩形、双指触控、笔/手指取消、异常捕获释放、陈旧手势清理与原有几何验证器集成。

必须在最新 HEAD 运行核心数学、平面数学、点投影、V5 工作台及静态网站五组 GitHub CI。浏览器模拟/Node 回归即便通过，仍不能代替 Android 真机不同触控驱动、ColorOS WebView、设备 DPR 与 native TextDetector 的现场验收；也不能据此证明 Cloudflare 正式版本已经发布。
