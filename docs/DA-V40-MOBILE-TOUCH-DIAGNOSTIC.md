# DraftAI 09 V4.0｜本地五点触控坐标自检

本专项服务于个人 AI 工程制图自动解题与 V5 动态作图系统的**真实图片识别质量测试**，不修改数学解题器。

## 为何增加

#308 已修复放大、滚动和多指错误标注，但自动化测试无法代替 OnePlus / ColorOS / 其他 Android 设备的真实浏览器触控。需要一个可在用户设备上亲自操作的自检入口，以便对坐标对齐异常复现问题。

## 页面操作

1. 在 `/labs/recognition-qa.html` 本地选择有权使用的原图，运行识图检测。
2. 点击「开始五点触控坐标自检」，图片上的橙色十字会依次出现于画面的中心、四个内角（归一化 20%/80%）；每次用手指或手写笔点击十字中心。
3. 页面计算实际触点与当前十字中心的**原图像素欧氏距离**，显示已测最大偏差。五次完成后显示平均/最大偏差。
4. 测试过程中可以用 #308 的按钮放大或缩小图纸、滚动查看；十字使用 SVG 的原图 viewBox 坐标，视觉标记半径约为 13 CSS 像素，缩放不会改变其几何位置。
5. 点击「结束自检」、更换照片或重新识别都会丢弃测试结果。原有识图候选、人工标注、SHA-256 文件基准和 TP/FP/FN 报告完全不变。

## 严格边界

- 这是**可视点击偏差自检**，包含用户主观目测点按误差、触控面积和浏览器渲染误差；不能声称测试出了硬件触摸驱动的真实物理精度或自动校正设备。
- 双指、`pointercancel`、离开 SVG 后抬手的无效指针不会被记为已完成点位，也绝不进入人工真值集。
- 自检数据只留在当前页面内存，不上传、不写入 localStorage，不进入数学解答和 V5 的证明流程。
- 该功能提供给 Android 真机使用，但**当前 GitHub CI 只覆盖算法和页面接线**；尚未实际拿到用户设备的真实触控结果，亦未独立确认 Cloudflare 当前部署的代码版本。

## 回归验收

`node --test tests/workbench/v40-photo-qa-touch-check.test.cjs`

测试中心及四点的目标坐标、已知偏差平均/最大值、缩放滚动映射、非法目标、双指取消、已有标注/指标不变以及页面自检按钮连接。

必须通过全部五个现有 GitHub CI；使用页面实际移动端体验的现场数据再决定是否需要修复 CSS/视觉区域，而不是仅凭模拟测试宣布 Android 兼容。
