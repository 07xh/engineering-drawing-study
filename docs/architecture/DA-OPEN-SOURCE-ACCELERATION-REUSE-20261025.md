## 1. 审计结论与本轮真实改动

- 已有 `core/numeric/` 自适应方向、射线与凸体证据。外部 predicates 只能作独立 oracle，不得第二套 M0。
- 已有 `engines/spatial/intersections/finite-orthogonal-cylinders.cjs` 有限正交圆柱**侧面—侧面**解析分支和端盖裁剪；现存 `tests/math/c3-*.test.cjs`、`tests/workbench/m5-*.test.cjs` 正在覆盖特定端点、投影、交汇和未证明状态。
- 已有 `core/projection/conventions.js` 第一角法、Geometry Scene、唯一 V5，不引入新的投影规则或播放器。
- 已有五项 GitHub Actions；`workbench.yml` 已有四分片，不重新实施。
- 本轮将成熟开源 **fast-check 4.10.2 (MIT)** 固定为**仅开发依赖**；在已有 `check.yml` validate workflow 的 `npm install` 后运行 `tests/property/c3-fast-check-geometry-oracle.test.cjs`。测试使用种子 20261025，可缩小失败参数。
- 新增测试使用与 M3 的 signed-sqrt 不同的**二分迭代**独立数值见证，并变换半径、X 轴偏移、三维平移、单位尺度和有限端盖：正例全四支 / 正向端盖单支 / 无交或相切保守退出。仍不等于连续拓扑、标准线型或真实习题的整题验收。

## 2. 可靠开源项目选择（先对照，后择优）

| 项目 | 放置位置及候选用途 | 验收前禁止行为 |
| --- | --- | --- |
| fast-check (MIT) | CI 的输入空间探索、缩减反例；本轮已接入 validate | 把随机样本通过当全局正确性证明 |
| Open CASCADE / OpenCascade.js (LGPL 相关条件须单独审查) | **独立开发/CI oracle**：CAD B-Rep、有限实体求交、投影/HLR 分段对照 | 直接把输出写入已验证 SolveResult、替换 M3/V5 |
| FreeCAD (LGPL 相关条件须单独审查) | 本地独立 CAD 脚本校验/参考 DXF，教材的参考答案与输入必须隔离 | 将私密 DWG/DXF、书本答案纳入公开构建 |
| Manifold (Apache-2.0) | C2 通用闭合网格布尔几何实验，单独校验接触/体积 | 把离散 mesh/渲染轮廓当解析曲线证明 |
| three-mesh-bvh (MIT) | 现有 Three.js 的射线求交**候选和性能优化**，与 M0/M5 结果对照 | 将离散射线采样升格为连续遮挡证书 |
| Playwright (Apache-2.0) | Android 等价视口、输入修订失效、唯一 V5 播放与二维三维高亮 | 视图截图作为数学证明或代替真实设备 |
| ezdxf (MIT) | DXF 原始标注/图层/块及校验器输入隔离 | 将 DWG 直接视为可靠 DXF，或将参考答案提供给解题器 |

**Open CASCADE 试验的最小协议**：在离线/可回退适配环境装载两个以 mm 为单位的有限实体；记录库版本/许可、输入哈希、操作(交/并)、B-Rep 有效性、3D 曲线端点、V/H/W HLR 可见/遮挡候选、数值偏差和运行时间；与现有 M3/M5 逐项独立比对。若 JS/WASM 包未导出所需 HLR API，先使用离线原生 CAD 参考程序，禁止按想象编写不存在的 API。**不得引入到公共页面**，除非通过功能、移动端内存/体积、性能和许可证验收。

## 3. 有重复时只保留更好的正式消费者，旧实现有用则作为 oracle

1. 按**数学正确/完整性、证据来源与失效、跨题型消费者、退化/大尺度稳定、性能、维护难度**顺序比较，不按代码行数或新旧日期判断。
2. 为重复段收集函数级消费者引用、公共 API 和参数/单位约束；至少覆盖两个不同实体/题型与正常、无交、相切、近退化、平移缩放、分支/修订失效。
3. 高质量公共实现做**唯一正式生产消费者**；有不同计算思路且可验证的旧实现保留为**隔离的测试 oracle**。否则在证据充分之后再删除无引用代码；原始 Git 历史保留。
4. 不机械去重专用 M3 解析方程；应去重复的向量/尺度校验、投影映射、SVG 作图样式等公共部分，但只在证明单位、方向、精度和错误语义等价后做。
5. 几何求解器不得导入 fast-check/第三方测试 oracle。所有测试期依赖均不得进入 Cloudflare 生产构建资源或浏览器 bundle。
6. 若性能恶化、证明范围缩小或实机失败：回滚相关 PR，旧解法仍作为对照；不宣称整体 C1/C2/C3 已完成。

## 4. 与课程交付次序并行，而不抢占

- **C1（优先交付）**：现有凸实体补第三视图、未配对点/线的歧义、防伪证据、正式棱线/线型到唯一 V5。独立 oracle/动画测试并行开发，但不要让 C3 重构阻断它。
- **C2**：复用已有多实体接触/几何 Scene，先补通用投影轮廓并集、接缝和遮挡交汇；Manifold 只辅助布尔拓扑对照。
- **C3**：已有有限两圆柱解析侧面交线继续保留；先用本轮随机反例扩大可复核输入，再补端盖全拓扑、连续遮挡、投影复线、正式线型及统一 V5；Open CASCADE/HLR 作为独立意见，不是认证器。
- **C4**：真实**无答案**习题盲测、Android 手写笔/触摸、生产 Active SHA，与工程图标准线型分别验收。

## 5. 发布与加速量化

- 每个 PR 保留最新版 HEAD 五项 CI completed/success、clean/mergeable、独立反例与当前 diff 审计；按 #152 squash-merge，不等待额外人工账户。
- 性能加速只能用固定几何数据集记录基线/候选的 median、p95、峰值内存、加载尺寸以及错误计数，至少覆盖低端 Android 场景；不可直接宣称倍数提升。
- GitHub PR 合并、Cloudflare 构建、Production Active SHA 和 Android 实机必须分别报告。
- **验收层次严格区分**：解析局部 M3 / 全局拓扑 / 连续可见性 / 端点和投影 / 标准线型 / ConstructionIntent→DAG→唯一 V5 / 真实陌生题图 / 线上生产。

## 6. 2026-10-25 正式执行规则：证据优先与最优复用

**适用优先级**：这是本文件最新、优先执行的开发方法；替代本文件和历史对话中所有与它冲突的旧提速步骤。#372 仍唯一规定数学/Geometry/证明/V5，#377 仍唯一规定 C0→C1→C2→C3→C4 近期交付优先级，#497 仍规定工作台与二维三维联动，#152 仍唯一规定 PR/CI/合并/发布。所有后续开发先核对最新 main，不从历史 SHA 直接推断状态。

### 停止旧的，不误删好的
- **停止**：F0–F5 旧交付顺序、逐题特判与独立动画、逐个二维再逐个三维重建、已有 M0–M5/Geometry Scene/第一角法/V5/四分片 CI/Cloudflare 部署的平行重建、无实际消费者的包装器堆叠、为了 PR 数量将一个功能拆成许多微型 PR、仅通过样例或静态图片宣称数学和 V5 完成。
- **保留**：已证明正确的专业解析算法、独立数学反例、已有原生公用实现、有效旧 URL、仍有消费者的旧工具、必要兼容层、可以做 oracle 的不同数学方法、历史提交。停止旧计划不等于删除旧资产，不因名字含 legacy 就批量删。
- **现行单链**：已人工确认 ProblemDraft → M0/M1/M2 → 专业 M3 → 唯一版本化 SolveResult → 只读共享 Geometry Scene 与第一角法 V/H/W 及同源 3D → M5 拓扑/连续可见性/工程线型正向证据 → ConstructionIntent → ConstructionStep DAG → 唯一 V5。任何第三方引擎不得改写这条链的数学资格或代替 V5。

### 强制先查重再开发
1. 每个新函数、适配器、框架和依赖先从**最新 main**列出现有实现、真实调用者、相关 Issue/PR、测试 oracle、构建白名单和旧 URL；指出实际未满足的公共能力缺口。优先复用 #630/#633/#635/#640 等已有事件/来源/端点与线型门禁；新 PR 必须先核验它们在当前 main 的状态。
2. 对现有 A、重复旧实现 B 和成熟 OSS C 以**同一输入与计量单位**独立比较：数学正确性与证明范围先于速度，随后比较退化和尺度稳定、两类以上真实消费者、性能/内存/包体、许可证/安全、维护成本、回退能力。记录版本、输入哈希、输出差异和失败反例，禁止凭新旧或行数定优劣。
3. **一个最优正式生产消费者**：只在跨题型等价测试成功、所有生产调用点迁移完成后择优保留。独立且有价值的第二种实现留在隔离测试/离线 oracle；无引用、无证据价值的冗余实现经动态入口、打包、测试、URL、历史兼容及回滚审计后删除。不能强删专业 M3 方程、猜测可见性或同时保留两套生产真相。
4. 引入 OSS 必须证明解决已有缺口；若现有实现更稳健则**不引入**。所有新增库核验准确版本/许可、分发要求、来源、锁文件、供应链、移动设备开销，不把大型 CAD/WASM 内核未经评测直接打包到浏览器。

### OSS 采用层次与实际试点
- **已经使用**：fast-check 4.10.2 开发期数学属性/缩减反例，仅测试 oracle，不能签发全局正确性。
- **第一批独立离线数学核验**：OCCT/Open CASCADE（B-Rep、有限实体相交、HLR 隐藏线）、SymPy（解析分支/相切/退化）、robust-predicates（方向谓词对照）；特别核验坐标方向、第一角法、有限域、浮点误差、不同 HLR 行为及许可。OCCT/FreeCAD 输出不得混入实际 SolveResult 或教材原题输入。
- **第一批静态去重审计**：dependency-cruiser 和 Knip 寻找循环依赖、不可达导出、候选重复代码；静态分析结果不能自动证明无动态调用、无生产白名单或无原 URL 用户。
- **第二批有条件试验**：FreeCAD/Manifold/polygon-clipping/ezdxf 用于离线 B-Rep、布尔拓扑、适用二维轮廓及 DXF 图元独立对照；Playwright 用于真正浏览器的审阅、失效、二维三维联动和唯一 V5 事件回归。
- **先量化再决定**：three-mesh-bvh、OpenCV.js、Tesseract.js、SVG 曲线工具，只在射线性能或识图/显示具体瓶颈存在时评估；图像候选必须人审/双比例/来源绑定，离散 mesh/采样点不能成为连续曲线证明。

### C1/C2/C3 共用核心的最短实施路径
1. 同一真实几何来源的 V/H/W 投影事件与排列：原始/新生源边、真实交点、重叠、相切、分割端点、源 ID、XYZ 深度别名和纸面非物理交叉；先消费已有实现再补缺口，避免新的平行事件系统。
2. 同一最终开区间的实体并集外轮廓、前方深度排序、连续可见性、端点上下游关系、标准线型正向证明；不确定一律 undetermined。
3. C1 优先签收可信棱线与补第三视图。C2 仅扩展真实接缝与多实体拓扑；C3 仅扩展专业解析曲线、端盖及切触拓扑，并复用公共投影/遮挡/线型管道，严禁每种圆柱参数开发专属动画。
4. 完整数学来源+拓扑+连续遮挡+端点关系+工程标准都通过的单个最终线段，才允许 ConstructionIntent → DAG → 原 V5 正式播放。任意缺证需保守阻断；二维、3D 和唯一时间轴同 revision、branchId 和身份。

### CI 加速必须保留门禁
- 已有五项 GitHub Actions；workbench 已四分片，勿再重建。validate 有大量顺序历史脚本，先测每步耗时/失败率/缓存收益，再考虑锁文件/npm ci、缓存、互不依赖步骤并行、分片均衡；最终合并仍需**实际 PR 最新 HEAD 五项完成且全部成功、mergeable=true、diff/隐私/许可证/独立反例审查**，依 #152 squash-merge。
- 一个通用功能及其独立数学反例、真实消费者与回退放在一个可验收 PR；并行改动若使 base 过期须同步并重跑真实最终 HEAD，绝不使用旧绿灯。
- 不改原生 Cloudflare main→Workers Builds 发布路径。分别报告提交、CI、合并、构建、Production Active SHA、真实浏览器/Android 和无答案原题验收，禁止把一种当另一种。

### 真正衡量提速
- 固定 C1/C2/C3 各至少一个跨参数/退化/不支持/版本失效的非私密数学基准；研发交付用“共性能力从明确缺口到可用 V5/独立验收并合并的实际耗时”衡量，**不以 PR 数或提交数**衡量。
- 每次优化记录：实际消费者数、被可靠替代的重复实现、数学失败样本与 fail-closed、真实题型签收数、CI 壁钟时间、median/p95、峰值内存/包体、回滚。
- 没有基线与候选实测，不能宣传提速百分比；在真实贡献不足/许可或性能未通过时退回旧解法，不因引入开源库牺牲可靠性。
