4. **保留经证明的既有算法**：现有有限圆柱解析 M3、原生 M0 稳健谓词、投影及跨视图源关系继续作为优先核心；CAD 候选不得覆盖它们。曲线离散采样、B-Spline 拟合、网格布尔、有限射线抽样只是候选/反例，不是整条连续曲线及隐藏线的证明。

### 7.2 通用数学验证链：复用已有 M4/M5 消费者，而非造第二个证明器

1. **完整源拓扑**：复用已合并的实体源边/解析曲线/面交线图、端盖线和局部布尔证据。复核整个有限域、曲线分支、真实 3D 接点与切触，识别投影纸面同点但三维源不同的别名；不得以 2D 交叉冒充 3D 连通。
2. **投影事件与最终轮廓**：复用公共 V/H/W 第一角法、现有曲线-直线/直线-直线事件分段、来源去重、前方深度排序、实体交/并/差真实保留表面，独立证明整条原始与新生投影轮廓来源覆盖。
3. **连续可见性与线型**：对每个最终开区间及两侧端点，证明射线无遮挡、深度切换、曲面/端盖连续接缝、合法相邻延续及适用 GB/ISO 工程线型规则。浮点初筛配合必要的自适应稳健谓词、独立不变量和有界/精确判定；遇到非支持奇异点必须 fail-closed，不能以采样密集度替代解析或严格有界证明。
4. **正式 V5 唯一出口**：只有一个最终动作的来源、完整拓扑、连续可见性、端点、标准线型、revision/branchId 全部独立通过，才由**既有** M5 正式动作 gate 签发 ConstructionIntent → DAG → 单一 V5。其余严格保留 undetermined 与零正式签发动作，可提供明确标注的非认证预览。禁止第二套 CAD→V5 路径或自行造一套线型判定结果。

### 7.3 冻结接口后并行三个工作流

- **A｜CAD 候选/独立 oracle**：以已经合并的 #716（C1 OCCT B-Rep/HLR）及 #717（C3 有限正交圆柱 lateral-lateral 真正 OCCT 对照）为**局部事实起点**，扩展完整候选曲线/端盖/面拥有者/切触/布尔/隐藏线事件；记录精确版本、输入哈希、单位、范围、数学偏差和失败反例。两 PR 的当前范围并未实现完整全拓扑或标准线型。
- **B｜公共数学/工程规则**：只扩展现有 C1/C2/C3 M4/M5 的真实消费者，优先补全全局轮廓、真实连接、连续遮挡、标准线型的共同欠证，不新增竞争性求解/证明核心。一个通用抽象须经至少两类不同对象/题型实际消费者与独立反例验证。
- **C｜工作台/V5/回归**：复用 V7 同源 Geometry Scene、首角三视图、原 V5；先接已验证图元、统一修订失效、双向选中与真实浏览器/Android 测试，绝不让 UI 根据预览自行证明曲线或决定线型。
- 三工作流在统一输入/输出、源 ID、revision/branchId、坐标单位契约冻结后并行；同一文件的变更需同步，PR base/HEAD 变化必须复核并重新跑最新 HEAD CI；一个完整通用功能尽量配套独立反例、消费者、回退在一个可验收 PR 中，避免只堆包装层。

### 7.4 验收、发布与效率量化

1. **阶段门禁**：先完成同输入下 CAD 候选与现有 M3 的三维/端盖/布尔差异审计，再完成共享 M4/M5 全局事件/区间/线型正向证明，最后完成真实 ConstructionIntent → DAG → 原 V5 整题动作。每项分别报告通过范围及仍阻断的事件，不以其中一步替代其他步骤。
2. **数学反例不得缩减**：至少含不同半径/轴偏移、有限端盖、交/并/差、无交/切触/近退化、多分支/遮挡切换、真实 XYZ 连接与纸面别名、平移/尺度/旋转、单位、伪造来源/候选、过期 revision 及版本分支变化；附独立数学或可靠 B-Rep 对照，严格保持未证状态。
3. **CI 与真实交付**：每个 PR 需检查最新 main、已有实现/调用者、变更与许可证/隐私、反例、合并可行性及**最新 HEAD 五项 CI 全部 completed/success**；若新增/触发 OCCT 独立 CAD CI，该项也必须通过，不以旧绿灯跳过同步。合格按 #152 squash-merge；GitHub 合并、Cloudflare 构建、Production Active SHA、Android 实机及无答案原题盲测单独验收。
4. **CAD 运行时谨慎**：OCCT/FreeCAD/SymPy 等默认仅离线/CI，不直接进入 Cloudflare Workers、网页和 Android；若未来作为正式运行时候选计算器，先对许可证与依赖分发、隔离/隐私、确定性、移动端体积/内存/p95、现有 M3 一致性、回滚做独立证明，仍不得绕过权威 M0–M5。
5. **真正衡量开发提速**：按从明确公共缺口到跨题型已验证真实消费、数学与 V5 完整签收的实际墙钟时长、失败反例发现率、复用范围、CI 耗时/峰值内存/包体比较；不得根据计划或 PR 数量声称已经提速若干倍或承诺数日完工。

## 8. 成熟开源库直接功能复用的评估与接入门禁（与 #372 最新规则一致）

1. **C1 OpenCascade.js / OCCT HLR**：先核实具体包版本、真实 HLR API、第一角法 V/H/W、源 B-Rep 面边身份和可见/隐藏候选输出；与已有 C1 #716/#718 正式消费者和独立 oracle 同输入比较。仅在来源映射、正确性、性能、许可证及回退均通过后可成为正式投影/隐藏线计算依赖；输出仍须 M5 证明才能签发标准线型。
2. **C2 manifold-3d**：评估真实闭合实体布尔并/交/差、接触/孔洞/非流形、精度与 mesh→解析源边映射；无法可靠追溯来源及连续可见性时只能作为候选或 oracle，不得凭 mesh 直接签发正式线型。
3. **二维 Maker.js**：评估编辑/约束输入、坐标单位、对象 ID、导入导出和人工确认 ProblemDraft 的兼容性；不得绕过 M2 约束证明、现有几何场景与 V5。
4. **采用决策**：每项先列出当前生产实现与调用者，使用固定真实输入、退化/伪造反例对照，记录版本/许可/资源/Android p95/包体、错误数、回滚方案；通过后一个可验收 PR 迁移正式消费者，保留可靠旧求解器或隔离 oracle。没有测试证据时只记为“待评估”，不得写成“已接入”。
5. **规则冲突消解**：本文第 1–7 节涉及“只可离线/候选/测试”及“绝对不得生产使用”的语句，均按本节与 #372 最新规则解释为**接入验收前限制**；接入验收后允许直接承担计算，但不能替代数学认证。若将来修改本文件，应同步清理旧绝对措辞，避免产生两套有效规则。

## 9. C1 整题交付优先：OSS 计算复用 × 正向证明 × 合并成块（2026-10-25 生效）

### 9.1 只按真实交付能力排期（P0）
- **P0-1 成熟 OSS 承担真实计算**：沿已合并的 OpenCascade.js 实际 HLR / OCCT B-Rep 运行消费者推进，不重复开发可见/隐藏线 CAD 内核；把 native 输出的真实来源 ID、V/H/W 坐标、单位、版本、模型修订、完整区间及三维端点接到现有 M0–M5 正向证明。现有实现若有严格证明且性能更可靠，继续复用，不因为“开源优先”盲目引入依赖。
- **P0-2 先交付可验收的 C1 补第三视图整题**：对真实无答案原题完成用户确认的几何条件 → 可解释的三维恢复/多解状态 → V/H/W 第一角法最终轮廓（包含可见/隐藏棱线）→ 真实三维端点/交汇、连续遮挡、前后深度排序和适用工程线型正向证明 → 原有 ConstructionIntent → ConstructionStep DAG → 唯一 V5 逐笔作图 → 同一场景的 2D/3D 对应与 Android 实机。缺证原样保留 undetermined，绝不猜实线/虚线；无解或多解不能伪装为唯一答案。优先完成能跨多个凸体、长方体参数变化、旋转和投影重合复用的公共阻断，不针对某一张题图硬编码。
- **P0-3 全局 M5 的实际阻断先于新包装**：优先解决真实 CAD HLR 输出与 M0 原始三维来源的一致性、完整区间微小缺口、端点和投影拓扑、闭合实体全部面/棱线的全局遮挡、适用 GB 线型。只有每个最终动作的全链证据齐全才允许原 V5 正式签发。若只获得局部证据，应清楚报告剩余阻断，不得将阻断清单误称已完成的正式解题。

### 9.2 合并成块交付，停止 PR 数量竞赛（P1）
1. **一个 PR 应尽量解决一个可复用且可验收的完整阻断**：包括真实计算/消费者集成、跨参数独立数学正反例、失败回退和必要 CI；相互依赖的短补丁优先合成一个 PR（或单一连续开发分支）。不为“新增状态字段、只增加包装器、只汇报 blocker、只调统计”独立开多个 PR，除非它阻断错误签收或生产事故。
2. 每次开工以最新 main、相关未合并 PR/Issues、真实测试和运行数据核验：先修当前最近的**数学阻断**，而不是按旧编号继续堆工作量。并行工作需隔离文件修改并在当前 HEAD 重跑 CI；冲突 PR 先核验再择优整合，不盲目覆盖。
3. **完成定义**依次独立记录：代码提交与 PR、当前 HEAD 完整 CI、合并 main、真实原题盲测及 V5/2D/3D、Cloudflare 构建与 Production Active SHA、Android 真机。GitHub 绿灯不是部署成功，局部 HLR 不是整题验收，生产 Active 未核对不得写“已上线”。
4. 不暂停 C2/C3 必要修复；但除明确回归、安全或阻断共享底层的任务，近期研发资源集中在 C1 的全局数学证明和整题交付。C1 完成后公共 M4/M5 直接服务 C2 组合体与 C3 相贯线，不重新建设求解器/动画。

### 9.3 每次推进的可核对报告
- 记录本轮**真实减少**的全局阻断类别、已经正式签发的完整动作、真实原题通过/拒绝统计、回归测试、CAD OSS 版本/许可证/性能影响、当前 SHA 与生产 SHA 差异。未做性能对比不得宣称几倍提速。
- 若新增证明只在真实 WASM 局部成立但无法签发整题，应报告“已完成局部数学证明，尚未交付可用 C1”，明确下一个可复用的阻断，而不是继续堆很多相似 PR。
- 本第 9 节覆盖本文件第 1–8 节中与「仅离线试验」「拆分成无完整消费者的微型 PR」「以 CI/PR 数量衡量交付」冲突的旧排期措辞；开源库通过验收后可作为真实功能依赖，但永远不得绕过 #372 唯一证明链。
