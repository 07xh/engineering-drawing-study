## 1. 正式产品定位和网站流程

**绘序是内置多种常见工程制图题型求解器的在线解题网站。** 多模态 AI 是参与题目理解、空间推理、求解方案规划与数学工具调用的综合解题入口，**不是仅 OCR/题型分类器**；同时保留完全无需 AI 的网站专用工具直接解题。二维/三维对应与动态逐笔作图是解题输出与解释方式，不是独立的主产品。

- **直接解题（不用 AI）**：题型入口 → 输入、绘制或导入已知条件 → 内置求解器 → 几何/标准验证 → 答案、步骤与对应展示。
- **AI 识图及综合解题**：照片/截图/工程图 → 接入多模态模型理解题意、图元/尺寸/投影、已知待求 → 用户核对低置信条件 → AI **推理空间关系、生成候选解法/可执行约束与构造顺序** → 编排调用或组合**同一套**内置解析、约束、投影与 CAD 工具进行真实计算 → 验证完整性、分支与工程线型 → 输出**答案 + 详细步骤 + 二维工程图 + 适用三维模型 + 唯一 V5 动态作图**。工具不能完整覆盖的复合题可由 AI 提出候选思路与需要的计算，但未经实算/验证不得称为正式答案；识图失败或 AI 不可用可手动输入。
- **空间题的 2D/3D 对应**：一个共享几何解产生第一角法 V/H/W、3D 可旋转解释、点线双向高亮和唯一 V5 同步。纯二维题不强制建模。
- **正式答案和预览严格区分**：求解证据、源/端点/拓扑、可见性或标准线型缺失时只能给候选、阻断原因或未支持，不能借 AI 文案/示意 SVG/采样补成“已解”。

## AI 输出自定义与解题思路（V11 新增必需能力）

**解题结果可按需生成和显示，不强迫每次都输出全部解释与图形。** 该设置属于 AI 解题与网站直接解题的共享结果展示层；用户可在解题前选择，解题后也可基于同一已验证 SolveResult 追加生成或隐藏部分内容，避免无意义地重复调用 AI/几何计算。

| 输出选项 | 默认 | 含义 |
| --- | --- | --- |
| 最终答案 | 开启 | 正式几何结果、完成图和题目结论（未验证必须醒目标记） |
| 解题思路 | 开启 | 用简洁文字解释已知/待求、核心投影/几何关系和拟采用的方法；不等于预先展示最终轮廓 |
| 详细解题步骤 | 开启 | 依据受验的 ConstructionIntent/Step，逐点逐线展示真实投影、辅助线、连接与实虚线依据 |
| 二维工程图 | 开启 | 对应题型的标准二维结果，遵守第一角法与认证线型范围 |
| 三维模型 | 空间题默认开 | 与二维共享 Geometry Scene，可旋转并双向点选；纯二维题自动标记不适用 |
| 动态作图 | 支持 V5 时默认开 | 唯一 V5 真实作图动画、暂停/回退/调速；无正式步骤时不能用预制演示冒充 |
| 结果验证说明 | 可选 | 已知条件对照、残差/分支、线型和模型完整性验证，不影响强制内部核验 |
| 文件导出 | 可选 | 对已生成且符合导出门禁的 SVG/PNG/步骤图等格式输出 |

- **讲解级别**：精简（答案/简要思路）、标准（主要作图步骤和关键依据，默认）、详细教学（关键点为何在此、辅助线如何转移、点线为何相连及虚实线理由）。即使用户关闭解题思路、详细步骤，计算内部的证据约束及安全验收仍必须执行。
- **预设模板**：仅答案、标准解题、详细教学、二维三维展示、自定义。用户可保存本机偏好并对单题覆写；模型调用应按选择的输出类型规划，避免为没勾选的三维/长篇讲解增加不必要消耗。
- **分离“解题思路”和“详细步骤”**：前者是便于学习的高层方法说明（不要求公开模型内部推理日志）；后者是从数学求解器/V5 的可复核作图动作生成的步骤。图文与每个对象/步骤 ID 对齐，不是先编答案再配文字。
- **结果复用与状态**：同一 problem revision / branch / SolveResult 按需切换已计算的结果视图；选项变化通常只重新生成展示/解释，不修改几何证据。用户修改题图/条件时必须使旧结果、3D 与 V5 同步失效。无相应可信计算/可视化证据时标记“不支持/未验证”，而非让 AI 编造。
- **多端体验**：设置采用少量开关和预设，移动端默认折叠高级设置；图纸区优先显示结果，思路与步骤可展开。直接工具求解也能选择答案/步骤/图纸，AI 独有的自然语言讲解按服务可用性启用。
- **验证**：分别测试只要答案、关闭解题思路但保留详细步骤、仅二维、空间题二维三维同步、纯二维题请求三维的拒绝/禁用、讲解级别切换、失败/未认证题关闭验证说明时仍不输出伪标准答案、恢复偏好和旧版本失效。不能将文档配置视为设置 UI 已开发。

## 2. 一级常见题型（按用户要解的题划分）

| 一级模块 | 真实解题目标 | 代表子项 |
| --- | --- | --- |
| **平面图形作图** | 已知尺寸/几何关系，构造符合条件的平面图形及作图步骤 | 正多边形、圆/线段等分、相切过渡（含圆弧连接）、斜度锥度、长圆/对称轮廓、复合平面图形 |
| **点线面投影** | 求作并解释点、线、面在各投影面的对应与位置关系 | 三面投影、实长/迹线等适用子题 |
| **三视图与补图** | 根据已有视图求缺失视图、补漏线与投影关系 | 已知两视图补第三视图、可见线/隐藏线 |
| **组合体** | 求解由实体叠加或切割形成的工程图 | 组合体读图、三视图、缺线、切割体 |
| **截交线** | 求基本体与平面相交产生的交线及各视图 | 柱/锥/棱柱/棱锥截交 |
| **相贯线** | 求两个立体相交的空间交线和投影 | 有限正交圆柱等有证范围 |
| **轴测图** | 按工程图学方法生成/解释轴测图 | 正等测、斜二测、由视图推轴测 |
| **综合工程图题** | 常见图学综合求解，逐类扩展适用范围 | 剖视/断面、尺寸标注与混合约束 |

**圆弧连接仅为“平面图形作图”内部的相切/过渡子能力，不允许作为一级首页模块或独立产品里程碑。** 保留现有圆弧连接求解器、旧页面和测试，后续用类型路由汇入该一级模块。**不能仅替换名称就宣称覆盖正多边形、斜度锥度等尚未验收的能力。**

每一子题型须维护能力矩阵：`现有计算入口`、`输入方式`、`证明范围`、`2D/3D`、`V5`、`真实题与移动端验收`、`状态（正式支持/实验预览/未支持）`。

## 3. 提速交付顺序：可并行，不以 C1 全局阻塞

1. **P0 现有功能真正可用**：盘点 main 已合并求解器/页面、可复用消费者；统一网站解题中心与“平面图形作图”等一级模块，保留旧深链；优先把点投影、平面几何子工具和其他确有数学证明的能力接到直接解题。每项真实输入 → 答案 → 逐步作图 → 页面验收，不以按钮/链接和 PR 数代替能力。
2. **P1 常见题型广覆盖**：C1 三视图（仍集中解决 HLR/M4/M5 未签收）、C2 组合体（复用 #896 OCCT 布尔历史与 Cone Lab）、C3 相贯（复用有限圆柱解析与 #1079 导入候选）分别形成完整题型闭环；点线面、截交、轴测等已有子模块可独立交付，不等待 C1 数学问题全部解决。
3. **P2 多模态 AI 综合解题**：引入可替换的模型服务层：题图语义解析/投影对应 → 已知待求及不确定性记录 → AI 解法推理、约束构造与候选三维空间模型 → 编排已有几何/CAD/投影计算工具 → 独立数学和线型校验 → 图解/详解生成。不要把 AI 限制为固定题型路由；对于综合题可组合已有工具与推理步骤，但任何新几何都必须经同一 M0–M5 可信消费者认证，未验证仅显示候选。模型凭证仅保存在受保护服务端/Worker，不进静态前端和公共仓库；图片处理限额与私密存储按权限分开实施；AI 不可用时保留直接工具入口。未实现前禁止宣称“上传任意图即自动解题”。
4. **P3 统一输出体验**：2D 正式作图结果、适用的同源 3D、双向选中、真实投影辅助线、逐步解释和唯一 V5 时间轴；改动条件或切换分支同时使旧数学结果与动画失效。Android 平板/手机、桌面浏览器及导出单独验收。

**研发选题规则**：优先选择可复用、能解决一类常见题、已有代码最多、距离端到端完整验收最近的能力；不要因 C1 的一个困难反例停止所有其他题型。对 C1/C2/C3 等难题保留独立高质量数学攻关，不以覆盖速度降低证明标准。

## 4. 复用资产，不造重复系统

- 现有 M0–M3、二维解析几何和空间专业求解器继续作为唯一正式计算体系；现有 OCJS/原生 OCP/OCCT、HLR 与布尔证明按证明范围使用。
- Cone Lab 已合并的拼装、模型 JSON、解析实体导入作为组合体/空间解释和人工构型辅助，未获 M4/M5 正式线型证据不得把其 3D 预览叫作标准答案。
- 第一角法投影约定、SolveResult、Geometry Scene、ConstructionIntent/ConstructionStep DAG、唯一 V5 全站复用；不另造圆弧播放器、三视图播放器、轴测图播放器或并行 Scene。
- AI **参与解题推理**，但其候选约束、作图方案、三维形体和文字解法必须和几何核可复算证据绑定；不能由模型直接生成无数学依据的实虚线/坐标。未经确认的识别候选、未验证的复合题分析不能直接签发正式 SolveResult。必须能将 AI 的每步推理与正式图元、计算工具结果、V5 步骤关联。

## 5. 开发组织与 PR/CI 提速

- **三路并行**：A 专业题型数学与证明；B 直接解题工作台/AI 输入/2D3D/V5 消费者；C 独立题目、回归、Android 与发布核验。共用接口版本，冲突文件由一个集成分支串行修改。
- **按能力闭环提交**：一个 PR 尽量包含该题型实际求解消费者、输入/结果 UI、真实步骤、正反例与回退；避免只加诊断字段的碎片 PR。先看最新 main 和相关重叠 PR，再复用已验收实现。
- **长期 PR**：#1075、#1079 和其它未合并分支逐文件比对保留有效成果，不默认合并，不重复建造；旧计划和无消费者代码须经过引用/数学/CI 审计方能删除。
- **门禁**：适用的实际 CAD、四分片工作台与核心数学/站点 CI 必须在当前 HEAD 成功；PR 合并和 Cloudflare Production Active/Android 实机分别核验；未知生产自动触发时不合并。保持 #152 的授权范围。
- **发布**：优先受限但真实可解的功能，显式标明支持范围。过去的 2026-11-20 争取目标已经过去，不视为发布证明，也不擅自设定新的保证日期。

## 6. 统一验收和每轮报告

每个一级模块按代表性的**陌生、无答案输入**验收，并按子题型统计：可直接输入并求解的数量、正确完整题数、数学未签收缺口、正式 V5 逐笔步骤、AI 对图元/投影/尺寸/题意的识别准确度、**AI 解法规划与工具编排实际成功率**、AI 推理文字与已验算图元对应性、2D/3D 同源关系（适用时）、浏览器/Android 真机状态。验收必须覆盖未见综合题、欠约束/多解/错误识别、AI 模型不可用和独立直接工具解题。

平面图形作图必须至少分别验收**多边形/等分、相切过渡、斜度锥度、复合轮廓**等代表性子题型；“圆弧连接可解”不能独自签收整个一级模块。空间题仍须验证第一角法、端点拓扑、全原始参数区间的连续遮挡与线型、GIVEN/ANSWER 隔离，缺证 fail closed。

每轮记录：本次已实现/未实现的功能、真实独立整题通过数、可复现阻断减少数、最新 main/PR/HEAD/适用 CI、设备实测、Cloudflare Active SHA；不得把更新文档、合成示意、UI 展示或 CI 绿灯写成正式解题交付。
