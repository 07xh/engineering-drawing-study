# DraftAI｜唯一现行“整题交付优先”开发规则（2026-10-27）

> **正式替换旧开发计划与加速规则。** 原文件路径保留仅为兼容仓库历史链接；旧文件的第 1–11 节已从现行正文移除，不再作为执行依据。Git 提交历史可追溯，但不是并行有效规则。原 F0–F5、按日期强制串行 C0→C1→C2→C3→C4、一次一个碎片 PR、把 OCI/CAD 只能用于离线 oracle 的绝对禁令及仅用 PR/CI 数量衡量进度，均停止执行。
>
> **不废止：** [#372](https://github.com/07xh/engineering-drawing-study/issues/372) 的 M0–M5 数学真实性、连续可见性、完整拓扑、来源/版本、正式工程线型门禁；[#152](https://github.com/07xh/engineering-drawing-study/issues/152) 的 GitHub 合并与发布边界；[#497](https://github.com/07xh/engineering-drawing-study/issues/497) 的单一 Geometry Scene/二维三维联动/唯一 V5；[#380](https://github.com/07xh/engineering-drawing-study/issues/380) 的教材真实题型对照。**唯一短期交付总单为 [#377](https://github.com/07xh/engineering-drawing-study/issues/377)。**

## 1. 产品目标与唯一工作单位

产品仍是**个人 AI 工程制图自动解题与动态作图系统**，不是教学课程网站或通用 CAD 软件。交付单位不再是“一个证明字段、一个微型 PR、一段演示视频”，而是**明确适用范围内的一类真实题目的完整可操作闭环**：

经审核题目条件/真实源数据（ProblemDraft） → 现有 M0–M3 可信空间几何/分支 → 同一 Geometry Scene 与第一角法 V/H/W、同源 3D → M4 原始来源/投影事件/端点拓扑 → M5 全局完整源区间、连续遮挡和工程线型证据 → ConstructionIntent → ConstructionStep DAG → **唯一 V5 实际逐笔绘制** → 独立无答案题、浏览器/Android、生产部署分别验收。

只有满足当次适用范围全部数学义务的线段/曲线段，才能签发正式实线或虚线；缺证、极小但正长度的缺口、歧义、欠约束、多解未选、无交或不支持均明确标注 **`undetermined`/拒绝**，绝不猜测答案或凭 CAD 截图、采样数值、局部 CI 直接升级。

## 2. 依赖驱动的交付顺序（不再按僵硬日历串行）

1. **C1 补第三视图首先取得完整验收**：直接复用最新 main 已有的两视图候选、凸体几何、OpenCascade.js 真实 HLR、全局 M0/M4/M5、审核后 DXF GIVEN → 唯一 V5 入口和答案隔离比较。优先完成真实原始来源所有正长度区间、三维端点、投影重合、标准线型、陌生原题盲测；只对认证通过的受限凸体类型宣布支持。
2. **C2 基础组合体并行推进不依赖 C1 UI 结束**：复用已合并 #880–#896 的原生 OpenCascade/OCP 布尔历史及**同一运行** M0/M4/M5 证明包，从完整 3D 边/面/顶点来源和视图区间分割直接接统一正式线型与 V5。不得重新建立平行布尔引擎、重复全量来源计算或绕过未签收的 2D 纸面别名。
3. **C3 受限有限正交圆柱相贯并行数学消费**：保留已验证的有限圆柱解析 M3、端盖、真实 3D 连通/投影事件与 M5 连续证明，复用同一个 M4/M5 事件/来源/线型与 V5 桥。不得为每种半径、端盖或教材题另写播放引擎或曲线特判。
4. **工作台/识图/移动端与真实题并行**：已审结构化条件或经可信 DXF 转换可直接供第一轮整题验收；通用照片 OCR **不是** C1/C2/C3 数学闭环前置条件。图片识别不确定就人工确认，不用参考答案反向构造输入。
5. **复杂组合体、非典型相贯、更多截交/曲面及任意原始题图**是后续受控扩展；不把受限第一版称为全题型完成。

**2026-11-20 仍为第一版受限学习工具的争取验收目标，不是保证发布日期。** 任务根据“已认证消费者”和剩余真实阻断滚动推进；C1 未完成也不阻止 C2/C3 的独立真实数学增量，但不允许假称三者均已交付。不得以重新压缩范围、跳过证明或跳过原题来制造“提前完成”。

## 3. 开源/成熟项目：直接复用，先证明后信任

- **优先已有正式消费者**：OpenCascade.js 真 HLR 用于 C1；原生 OCP/OCCT 同运行时布尔源历史及 #896 proof pack 用于 C2；现有有限圆柱解析 M3 + 真实 B-Rep 对照用于 C3；fast-check 用于独立反例探索。Manifold、Maker.js、FreeCAD 等仅在已有消费者不足且证明收益明确时再评估，不同时维护重叠核心。
- CAD/OpenCascade、WASM 或其他可靠库**允许承担实际几何计算**，不再被永久限制为“仅离线候选”；但库输出不等于完整数学证明或线型授权。每项保留原始源 ID/三维 XYZ/单位、branchId、revision、库固定版本、源几何哈希、完整区间和错误语义；必须由现有 M0–M5 证据消费者独立签收。
- 一次评估版本兼容、真实 API、许可证与分发、WASM/包体、内存与 Android 性能、确定性、回退；没有数据不宣称速度倍数或移动端兼容。
- 保留已证明的最好实现作为**唯一权威计算/播放消费者**，另一个独立可靠方法可以保留为 oracle；删除无消费者重复代码前必须通过旧新反例对照。禁止第二套数学系统、SolveResult、Geometry Scene、标准线型签发器、第一角法投影或 V5。

## 4. 真实教材输入的并行通道

- 对已有教材原始 DWG，必须验证源文件哈希，用可信 ODA/LibreDWG 转 DXF 后人工审核原题条件的完整性、坐标/比例、视图身份；**GIVEN 与 ANSWER 隔离**、保留源句柄。转换器不存在时如实报告阻断，不使用缩略图或猜测几何代替向量输入。
- **先运行解题器，后解封独立参考答案作双向线型/几何比较**。报告是合成接口测试、真实教材题盲测还是未见原题；严禁答案泄漏入求解器或公开仓库/网站。
- 真实照片 AI 识别和触屏确认继续并行；当前可使用经过人工审核的结构化数据/DXF GIVEN 作首次正式交付，不需要等待泛化 OCR。

## 5. 一次对话/一次 PR 尽可能交付完整有价值的相关工作

1. **开始前审计**：最新 main SHA、开放 PR（尤其重叠旧 C1 分支）、已合并代码调用者、当前数学反例、CI 和产品真实阻断。能修复/整合已有同主题 PR 则不新开重复 PR；旧 PR 必须逐个确认差异后再择优整合/关闭，不进行无审计的批量删除。
2. **按真实阻断成组开发**：一轮应尽量包含真实生产消费者、可复算正向证明、独立反例、真实 DOM/V5 接入、CI/回退；同主题修改合在一个可审查 PR，避免每个统计计数、包装器、测试断言一张 PR。安全缺陷/主线阻断可单独修复。
3. **允许并行只读与不同责任文件**：独立几何/对照、数学证明、工作台消费者可以在接口与 revision 冻结后并行；同一文件/分支写入串行，任何基础 SHA 改动后重新校验。
4. **自动连续推进的边界**：在**实际调用的单次执行/已建立的自动任务**内，按依赖顺序尽可能完成多个相关工作单元，遇失败先修复，不人为只创建分支就终止；不能宣称聊天之外无人触发也会无限后台开发。
5. **合并**：当前 PR 最新 HEAD 的全部适用检查真实 `completed/success`、无冲突、许可隐私差异与反例合格后，可按 #152 使用 `expected_head_sha` 直接 squash-merge；不得跳过失败、过期、等待/取消或不适用却应当强制的真实 CAD 检查。GitHub 合并授权**不是**主动 Cloudflare 生产部署/配置变更授权。

## 6. CI 提速而不减少验证覆盖

- 保留已有 workbench **四分片**及五项常规检查，不再重建；按受影响代码要求执行 C1 真 OpenCascade.js WASM/HLR 与 C2 pinned OCP 原生正向测试，**禁止把 skip 作为 positive pass**。
- 先记录关键流水线的运行时长、依赖下载、缓存命中/失效、重复运行来源和失败点；有量化收益再引入锁文件缓存、路径筛选、工件复用和去重。必需检查/受影响依赖仍全跑，不为了绿色 CI 改为静默跳过或仅跑 synthetic。
- 同一提交的 CI 绿灯不是数学整题证明。PR HEAD、合并后 main、真实原题、浏览器/Android、Cloudflare Production Active SHA **独立留证**；不能把任意一个替代另一个。

## 7. 每轮报告和下一步判定

每轮交付只记录可核验事实：原 main/HEAD/merge SHA、改动文件与消费者、真实正向/反向数学结果、首次成功的**完整整题**与 V5 正式动作数量、仍拒绝的正长度缺口/别名/分支、真实原题 GIVEN 与 ANSWER 隔离状态、GitHub Actions 每项结果、Android/浏览器与 Cloudflare Active 是否确证。指标优先是**整题合格数、真实阻断减少数、从问题到可用消费者的墙钟耗时**，其次才是 PR 数或测试总数。

若一轮仅新增诊断而未减少真实整题阻断，应优先将现有证明交给实际 M4/M5→V5 消费者，或清楚报告下一项不可跨越的数学缺口；绝不伪造完成百分比、上线、自动化执行或承诺工期。
