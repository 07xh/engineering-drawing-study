- 已有 `engines/spatial/intersections/finite-orthogonal-cylinders.cjs` 有限正交圆柱**侧面—侧面**解析分支和端盖裁剪；现存 `tests/math/c3-*.test.cjs`、`tests/workbench/m5-*.test.cjs` 正在覆盖特定端点、投影、交汇和未证明状态。
- 已有 `core/projection/conventions.js` 第一角法、Geometry Scene、唯一 V5，不引入新的投影规则或播放器。
- 已有五项 GitHub Actions；`workbench.yml` 已有四分片，不重新实施。
- 本轮将成熟开源 **fast-check 4.10.2 (MIT)** 固定为**仅开发依赖**；在已有 `check.yml` validate workflow 的 `npm install` 后运行 `tests/property/c3-fast-check-geometry-oracle.test.cjs`。测试使用种子 20261025，可缩小失败参数。
- 新增测试使用与 M3 的 signed-sqrt 不同的**二分迭代**独立数值见证，并变换半径、X 轴偏移、三维平移、单位尺度和有限端盖：正例全四支 / 正向端盖单支 / 无交或相切保守退出。仍不等于连续拓扑、标准线型或真实习题的整题验收。

## 2. 可靠开源项目选择（先对照，后择优）

| 项目 | 放置位置及候选用途 | 验收前禁止行为 |
| --- | --- | --- |
| fast-check (MIT) | CI 的输入空间探索、缩减反例；本轮已接入 validate | 把随机样本通过当全局正确性证明 |
| Open CASCADE / OpenCascade.js (LGPL 相关条件须单独审查) | **独立开发/CI oracle**：CAD B-Rep、有限实体求交、投影/HLR 分段对照 | 直接把输出写入已验证 SolveResult、替换 M3/V5 |
| FreeCAD (LGPL 相关条件须单独审查) | 本地独立 CAD 脚本校验/参考 DXF，教材的参考答案与输入必须隔离 | 将私密 DWG/DXF、书本答案纳入公开构建 |
| Manifold (Apache-2.0) | C2 通用闭合网格布尔几何实验，单独校验接触/体积 | 把离散 mesh/渲染轮廓当解析曲线证明 |
| three-mesh-bvh (MIT) | 现有 Three.js 的射线求交**候选和性能优化**，与 M0/M5 结果对照 | 将离散射线采样升格为连续遮挡证书 |
| Playwright (Apache-2.0) | Android 等价视口、输入修订失效、唯一 V5 播放与二维三维高亮 | 视图截图作为数学证明或代替真实设备 |
| ezdxf (MIT) | DXF 原始标注/图层/块及校验器输入隔离 | 将 DWG 直接视为可靠 DXF，或将参考答案提供给解题器 |

**Open CASCADE 试验的最小协议**：在离线/可回退适配环境装载两个以 mm 为单位的有限实体；记录库版本/许可、输入哈希、操作(交/并)、B-Rep 有效性、3D 曲线端点、V/H/W HLR 可见/遮挡候选、数值偏差和运行时间；与现有 M3/M5 逐项独立比对。若 JS/WASM 包未导出所需 HLR API，先使用离线原生 CAD 参考程序，禁止按想象编写不存在的 API。**不得引入到公共页面**，除非通过功能、移动端内存/体积、性能和许可证验收。

## 3. 有重复时只保留更好的正式消费者，旧实现有用则作为 oracle

1. 按**数学正确/完整性、证据来源与失效、跨题型消费者、退化/大尺度稳定、性能、维护难度**顺序比较，不按代码行数或新旧日期判断。
2. 为重复段收集函数级消费者引用、公共 API 和参数/单位约束；至少覆盖两个不同实体/题型与正常、无交、相切、近退化、平移缩放、分支/修订失效。
3. 高质量公共实现做**唯一正式生产消费者**；有不同计算思路且可验证的旧实现保留为**隔离的测试 oracle**。否则在证据充分之后再删除无引用代码；原始 Git 历史保留。
4. 不机械去重专用 M3 解析方程；应去重复的向量/尺度校验、投影映射、SVG 作图样式等公共部分，但只在证明单位、方向、精度和错误语义等价后做。
5. 几何求解器不得导入 fast-check/第三方测试 oracle。所有测试期依赖均不得进入 Cloudflare 生产构建资源或浏览器 bundle。
6. 若性能恶化、证明范围缩小或实机失败：回滚相关 PR，旧解法仍作为对照；不宣称整体 C1/C2/C3 已完成。

## 4. 与课程交付次序并行，而不抢占

- **C1（优先交付）**：现有凸实体补第三视图、未配对点/线的歧义、防伪证据、正式棱线/线型到唯一 V5。独立 oracle/动画测试并行开发，但不要让 C3 重构阻断它。
- **C2**：复用已有多实体接触/几何 Scene，先补通用投影轮廓并集、接缝和遮挡交汇；Manifold 只辅助布尔拓扑对照。
- **C3**：已有有限两圆柱解析侧面交线继续保留；先用本轮随机反例扩大可复核输入，再补端盖全拓扑、连续遮挡、投影复线、正式线型及统一 V5；Open CASCADE/HLR 作为独立意见，不是认证器。
- **C4**：真实**无答案**习题盲测、Android 手写笔/触摸、生产 Active SHA，与工程图标准线型分别验收。

## 5. 发布与加速量化

- 每个 PR 保留最新版 HEAD 五项 CI completed/success、clean/mergeable、独立反例与当前 diff 审计；按 #152 squash-merge，不等待额外人工账户。
- 性能加速只能用固定几何数据集记录基线/候选的 median、p95、峰值内存、加载尺寸以及错误计数，至少覆盖低端 Android 场景；不可直接宣称倍数提升。
- GitHub PR 合并、Cloudflare 构建、Production Active SHA 和 Android 实机必须分别报告。
- **验收层次严格区分**：解析局部 M3 / 全局拓扑 / 连续可见性 / 端点和投影 / 标准线型 / ConstructionIntent→DAG→唯一 V5 / 真实陌生题图 / 线上生产。
