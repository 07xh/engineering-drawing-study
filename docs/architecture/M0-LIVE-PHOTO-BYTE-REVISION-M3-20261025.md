# 2026-10-25: real photo file bytes → versioned native M0/M3 source

The live photo workbench now reuses existing `fingerprintLocalPhoto(file)` WebCrypto SHA-256 after a user selects the ORIGINAL local image. The lightweight `local-photo-byte-session` retains no photo bytes or filename, only the current file object in ephemeral memory, an epoch and a 64-hex digest; it invalidates immediately on file replacement and clear. An asynchronous old-file digest can NEVER repopulate a newer session; unavailable WebCrypto leaves the source unready. The local preview dimensions must be finite and match the existing typed ProblemDraft image dimensions.

The actual production `auto-fillet-live-entry.cjs` injects `getPhotoIdentity:()=>photoBytes.snapshot()` into the existing reviewed dimension UI. On initial review and on each live M3 solver preflight, `local-reviewed-dimension-draft-ui.cjs` checks the digest and file attachment epoch against the same current review source identity, source revision and dimensions. M0 `reviewed-draft-m3-isolation` uses `sha256-<original photo digest>` as the input image identity ONLY when the real browser provides the verified local file digest, retaining original pixel→model-mm checks from #685, geometric numeric parity from #686 and `imageSourceIndependentlyAuthenticated:false`. SHA enters its local change detector but is not a proof-certificate boolean. Before final transfer, photo bytes identity is rechecked against the same immutable selected File object and source binding and exact M0↔M3 geometry parity are still required. Private opt-in export independently recomputes original file SHA and rejects mismatched digest in the current evidence snapshot.

The UI keeps an optional `getPhotoIdentity` injection for legacy isolated fixture callers without an actual user-selected browser File; **the real production entry ALWAYS provides it** and therefore fails closed if hashing is pending or unavailable. New real WebCrypto tests demonstrate selected bytes, file swap, async hash race, invalid metadata and missing crypto. Real HTML tests demonstrate M3 preflight acceptance when the correct file digest is available and rejection on digest/attachment-epoch swap without changing any ProblemDraft numeric content. This is a real native source byte binding to M0 model-mm input, not an independent textbook-original/authenticity proof: any forged image with newly hashed bytes can still be accepted after human review. Neither photo provenance, global scale, 3D scene visibility, official line styles nor single V5 is certified.

No second math kernel, independent OCR engine, network upload, persistent storage or background worker was added. This is a single coherent PR rollback. Requires latest PR HEAD all five CI workflow families and workbench four shards + original summary; conflicts resolved before merge.
