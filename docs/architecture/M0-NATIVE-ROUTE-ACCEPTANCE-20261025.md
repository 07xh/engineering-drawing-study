# M0 native photographic source: machine-checkable acceptance route

The M0 registry previously listed a real reviewed-pixel-frame consumer, yet the static audit stopped scanning at `workbench/` and did not include `labs/` and `recognition/`. It could therefore never establish whether that core M0 helper was connected to the actual browser photo review and M3 execution entry. This PR extends existing `scripts/audit-m0-acceptance.cjs` without adding a second math engine: enumerate the native UI/static consumers and **fail validation** if a required file, explicit adjacent relative import or executable regression evidence path is absent.

Three documented native import routes are required: real local photo bytes → SHA256/epoch session → existing UI; M0 reviewed pixel converter → existing reviewed-draft M3 isolation → actual reviewed UI → live page; local photo SHA256 → rehashable private record digest → private evidence exporter → live page. The existing tests themselves are separate executable checks; this audit asserts their presence and the import route, NOT that a static import alone proves execution, independent photo authenticity, geometry correctness, Cloudflare production, V5, or whole M0.

The `reviewed-pixel-frame` remaining gate now differentiates **implemented local current-file byte content/epoch binding** from genuinely missing external textbook/original provenance, perspective and global scale uniformity. Status stays `provisional`. New tests independently sabotage required source imports and test paths and verify CI's fail-closed behavior. Existing 20 M0 module exact coverage and all previous regression requirements remain checked.
