# Private original-photo and reviewed M0/M3 dossier: reproducible byte→record evidence (2026-10-25)

The existing 08 local photo browser already hashes the chosen ORIGINAL image with SHA-256 when the user explicitly exports a private evidence dossier. The existing R0 and M0 math preflight gates validate dual rulers, ProblemDraft revisions and isolated model-mm conditions but do **not** know whether the actual photo bytes are identical to the subsequently exported manual review. This batch reuses the original SHA-256 and adds a second, domain-separated WebCrypto SHA-256 of the *entire bounded user-reviewed export record*, including original photo digest, image dimensions, actual candidates, source revision, reviewed draft, scale, actual M3 and optionally V5 audit.

No photos, filenames or external secrets are included: the existing local export now attaches `byteReviewBinding` after checking that file identity, detector generation and current evidence have not changed during BOTH async digests. The reusable `verifyPrivatePhotoCase(file,record,subtle)` requires explicit user-selected original bytes and recomputes BOTH hashes, independently of the declared record. It returns fail-closed `not-verified` after changed bytes (even same dimensions), edited annotations, revision, source role, M3 fields, invalid digest and insecure/unavailable cryptography. Tested against real Node WebCrypto SHA-256 (not a fixed fake cryptographic stub), plus existing actual HTML local private-export integration.

**Proof scope**: This is **reproducible content integrity and a portable evidence document**, not an HMAC/private signature or proof of source provenance, reviewer identity, real photo capture time, original being free of printed answers, geometry measurement correctness, global ruler uniformity or M0/M3/V5 official mathematical signoff. A malicious party controlling an altered file can recompute a fresh digest; independent source truth must still be corroborated externally. Live M3 remains under current ProblemDraft/dual-review gates; this optional explicit export does not silently authorize live M3.

Do not duplicate image hashing, add a second math solver or send source bytes over the network. Integrate with existing `fingerprintLocalPhoto` and local opt-in `attachPrivatePhotoCaseExport`.
