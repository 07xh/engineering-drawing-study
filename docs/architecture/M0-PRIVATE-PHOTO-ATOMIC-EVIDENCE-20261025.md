# M0 original photo private export: atomic full evidence revision binding

The existing opt-in native local photo export computed two independent SHA-256 values: one over selected original File bytes and a domain-separated second over the private review/math dossier. But it only checked `getEvidence` and detector generation during async work: candidate arrays, source role (including answer-marked vs unmarked), image preview dimensions and current M3/V5 session could mutate without advancing either generation or ProblemDraft revision. That could produce a legitimate cryptographic digest of a **mixed-time** source record.

Capture a single JSON-safe complete snapshot of the user-selected photo dimensions, role, detector candidates, reviewed M0 calibration and M3 evidence, and actual live V5 input *before* starting the first async digest. Re-check those SAME full input dimensions, role, candidates, evidence, generation, live math state and original File object after original-byte hashing, after building the case, and after the second record digest. Build the private dossier from the captured value only, not from newly queried mid-flight values. Invalid input and changes are fail-closed. The two previously merged cryptographic functions, existing M0/M3 math, user opt-in download and in-memory only photo handling remain unchanged.

Tests exercise real HTML opt-in input events during the FIRST WebCrypto digest (change candidate set but keep generation, change source role, change decoded dimensions), and during the SECOND digest (change live M3/V5 state). No file is downloaded for mixed source versions. This is snapshot integrity, not an externally signed photo authenticity proof or a substitute for first-angle/V5 mathematical signoff. Under #152 requires all five latest PR HEAD CI families, four workbench shards and stable aggregation, mergeable true before squash.
