# 图学课堂 · 知识动画与公开资料检索审核（阶段二）

## 当前可用功能

1. **知识卡动态图**：所有 31 张知识卡会匹配原创 V/H/W 视图教学模型；“下一步/上一步/重新演示”分阶段出现示例几何。
2. **代表点自由度**：调用 `labs/constraint-engine.js` 对原创演示中的一个点计算约束，显示 3 → 1 → 0 → 0。该数值**不代表**整道教材题、全部顶点、平面或曲面。
3. **习题联网检索**：在 28 道习题页手动点击“联网查找参考资料”，匿名访问维基媒体公开条目与 Crossref 文献元数据；不传输 PDF、用户涂鸦或 GitHub 凭据。
4. **自动方法识别与比较**：由现有局部扫描的任务类型匹配可选思路，比较不同方法的可能适用条件，给出“待核对”状态。仅以标题与关键词进行初筛，**不是正文事实审核**。
5. **原题答案安全闸门**：公开页面中的 `VerifiedExerciseSolutions` 现为空；所有 28 道仍处于原图部分复核状态，故真正教材答案线保持空，不播放猜测步骤。

## 资料来源和使用限制

- 用户上传《工程制图.pdf》：只作为已有知识卡的教材页码和概念依据；扫描图、全文和出版社答案不进入公开网站。
- `knowledge/research-ui.js` 使用 MediaWiki Action API 与 Crossref REST API。查询是**即时触发**，并非后台持续爬取；结果仅是来源候选，网络请求会受浏览器、接口限速及网站连通性影响。
- 原理资料可能与教材具体习题不同，不能按搜索结果自动画原题线。
- 官方接口说明：[MediaWiki 匿名跨站请求](https://www.mediawiki.org/wiki/Manual:CORS)；[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)。

## 逐帧教材答案的准入条件

每题需依次满足以下要求：

1. 有可追溯的教材原图版本、原题文字与清晰的所有已知条件；
2. 完整核对尺寸、同名顶点、轴线、隐藏线、点位和几何约束；
3. 独立求解并逐步复核每条辅助线为什么合法、是否在指定面或形体上；
4. 每一步经坐标和几何一致性验证，并审查可见性；
5. 经人工审核的 `verified-solutions.js` 配方与已审核原图版本一一绑定；
6. 经 `knowledge/solution-gate.js` 进行格式、安全边界及审核标志验证，才允许 `chapter-drawing.js` 绘制答案层。

当前核验模块的状态标志仅用于**代码/数据一致性审查**，不是密码学签名或独立第三方正确性证明。未来若加入管理员上传审核，应由受保护的服务端签名、审计并生成不可伪造的正式配方。

## 功能边界

- 本阶段**不是**联网自动答题、数学视觉识别、教材原题完整扫描复刻或 AI 全自动求解服务。
- 对 2-9-7、2-9-8 等局部扫描难以辨认形体类别的题，按**未知曲面形体**处理，不臆测为球体。
- 对当前所有部分原图：第一帧只展示能确认的原题已知几何；原题答案线保持未开放。原创演示页面的 SVG 与原题作图区严格分离。
- 公开检索不使用用户私钥；不保存任何 API Token 到仓库。

## 维护与验收

执行 `node scripts/check-visual-research.cjs`、`node scripts/check-knowledge.cjs`、`node scripts/check-line-projection.cjs`、`node scripts/build-static.cjs`。GitHub Actions CI 验证静态打包包含相关 JS 资源。

上线前还应在实际浏览器分别验证电脑/平板：知识卡切换动画、断网时检索报错且其他功能可用、两种外部来源都返回或独立降级、原题任意一道依然不能通过搜索开启答案线。
